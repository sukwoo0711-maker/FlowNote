# 합성 시연·검수 시나리오

`scenario.json`은 앱에서 직접 실행되는 스크립트가 아니다. 에이전트가 기존 테스트/데모 어댑터에 맞게 연결하고 실제 서비스로 저장한다. ID는 별명이며 실제 저장 ID를 매핑한다.

## 첫 시연

1. 전날 업무 A를 만들고 관찰 메모·진짜 PNG·제공된 합성 로그를 남긴다.
2. 다음 행동 한 줄을 지정한다. 앱을 닫고 같은 데모 저장소로 다시 연다.
3. 다음 날 A의 마지막 기록·이미지·로그·다음 행동을 다시 연다.
4. 캡슐에서 A에 새 기록을 남기고 완료한다. 중복 완료 요청도 검증한다.
5. 오늘 날짜 보고에서 새 메모와 완료 이벤트만 선택한다.
6. 전날 근거 N-A2를 **명시적으로** 추가한다. PNG만 포함하고 로그 파일은 제외한다.
7. 기간 밖 날짜 표시, 선택 PNG의 상대 링크, 합성 비공개 메모 토큰의 완전 제외를 확인한다.
8. 앱을 다시 실행해 ID·원문·자료·완료 이력·다음 행동 과거값을 확인한다.

## 데이터 안전

별도 demo DB/첨부/설정 경로를 사용한다. 테스트 clock 또는 초기 fixture 생성 시각으로 과거를 재현한다. 운영 시계/운영 사용자의 Entry 시각을 바꾸지 않는다. 매 시작마다 중복 시딩하지 않는다.

`synthetic-debug.png`는 본 패키지에 실행 증거로 첨부하지 않았다. 기존 테스트 도구로 유효한 합성 PNG를 만들고 해시·크기·디코드 가능 여부를 검증하여 첨부 경로에 연결한다. 이름만 있는 가짜 fixture는 허용하지 않는다. 네트워크 이미지나 회사 자료를 사용하지 않는다.

빈 날짜·한 줄 메모1개·같은 시각20개·연결 없는 이미지·출처 삭제·느린 query·초안전환·보고 스냅샷 갱신은 별도 분기로 실행한다. 정상 시나리오 데이터와 오류 주입 데이터는 분리한다.

## 보고 검증

본문·ZIP 파일 목록·manifest·추출한 파일에서 `PRIVATE-DO-NOT-EXPORT`가 없어야 한다. 전체 DB/초안/revision을 보고 ZIP에 넣지 않는다. 선택에서 제외한 sample-uart.log 자체와 파일명도 결과에 포함하지 않는다. PNG는 실제 존재하고 보고 상대 링크로 열려야 한다.

이 문서와 JSON의 기대 결과는 검수 목표이지 이미 통과한 결과가 아니다.
