# FlowNote V3 — 작업 에이전트 실행 지침

작성일: 2026-09-15
대상: 현재 FlowNote 저장소를 실제 수정·실행할 개발 에이전트
문서 성격: 구현 발주 지침. 코드 검토·Windows 실행·시장 검증을 완료했다는 뜻이 아니다.
이번 결과: 기존 앱을 보존하며 아래 핵심 흐름을 연결한 검증 가능한 개발 빌드.

> 기록 → 업무 연결 → 다음 행동 → 나중에 이어서 확인 → 완료 이력 → 선택한 근거로 보고.

## 0. 작업 계약 — 먼저 읽고 적용

당신은 기획서를 다시 쓰거나 새로운 아이디어를 제안하는 담당자가 아니다. 현재 프로젝트에서 아래 요구를 구현하고, 실제 실행 가능한 범위에서 테스트하고, 수정 빌드를 제출한다. 디자인 결정과 구현을 사용자에게 계속 되묻지 않는다.

### 0.1 우선순위와 이전 지침의 대체

회사 정책·권한·사용자 데이터 보존 및 현재 저장소의 필수 운영 규칙을 먼저 지킨다. 그 범위 안에서 사용자 최신 명시 요청 > 이 V3 명세 > 본 패키지의 검수표 > 기존 명세 순서로 제품 요구를 해석한다. 검수표가 명세를 몰래 축소하지 않는다.

- 기존 캡슐 v2의 **가시 표면 520×52 DIP, 무제목표시줄, 한 줄 입력, 작은 보조 패널**은 보존한다.
- v2의 ‘플로팅만 수정하고 메인은 손대지 말 것’은 이번에 대체한다. V3는 캡슐 보존 + 하루 화면 정돈 + 업무 이어하기 + 선택 보고를 허용한다.
- 기존 U0 승인 대기, 단계마다 종료, 사용자 승인 전 U1/U2 금지는 대체한다. 아래 단계들을 내부적으로 순서대로 수행하고 중간 승인 없이 계속한다.
- 기존 세로 메모장, 흰 다중행 입력폼, 상시 큰 TODO 패널로 복귀하지 않는다.
- ‘기록됨’을 실제 TextBox.Text에 넣는 구현은 금지한다. 성공 상태는 입력과 분리된 비편집 표시다.
- ‘다음 행동’은 사용자 입력이다. AI 추론, 타이머, 자동 분류 또는 프로그램 실행 상태 복원이 아니다.
- 가격·14일 체험·결제·마케팅 전략은 이번 런타임 구현 범위가 아니다.

`docs/product-v3/SUPERSEDED.md`에 실제 충돌 문서·구절·대체 규칙을 기록한다. 긴 지침을 계속 덧붙이고 서로 상충하게 방치하지 않는다. 본 문서는 `docs/product-v3/SPEC.md`에 보존한다.

### 0.2 범위

**구현:** 기존 품질 결함 수정, 선택적인 업무 연결, 다음 행동 한 줄, 업무 맥락을 다시 여는 화면, 완료·근거 연결, 선택 기반 보고 미리보기와 기존 내보내기 연결, 실제 회귀 검수.

**유지:** 기존 파노라마·업무별 보기·검색·백업·복원·수동 캡처·오프라인 저장. 기존 구현 상태부터 확인한다. 연결 대상인 기존 기능이 미완성이면 이번 흐름에 필요한 최소 부분을 구현하고 나머지는 정확히 보고한다.

**제외:** 신규 프레임워크/언어/서버/벡터 DB, AI/OCR, 자동 화면·클립보드 수집, Jira API·SSO 우회, 클라우드 동기화, 근무·집중시간 추정, 모바일, 팀 관리, 결제·라이선스, 광고·원격 분석, 새로운 배경 블러 엔진.

### 0.3 기존 작업 보존

실제 저장소와 변경 상태를 확인한다. 사용자의 미커밋 파일을 reset/clean/삭제하지 않는다. 동일 앱을 다른 프레임워크로 새로 만들지 않는다. 기존 ViewModel·서비스·DB를 재사용한다. 원격 push/PR/배포/설치·보안 설정 변경은 이번 지시의 자동 승인에 포함되지 않는다.

코드가 없는 경우 임의 프로젝트를 만들어 현재 앱을 수정했다고 하지 않는다. 확인한 경로와 필요한 저장소를 보고한다. Windows GUI가 없으면 가능한 코드·로직 검수는 수행하되 실제 창 검수는 NOT RUN으로 남긴다. 제한을 우회하지 않는다.

## 1. 구현할 제품 가치 — 하나의 완주 시나리오

첫 검증 대상은 여러 이슈를 오가며 캡처·로그를 남기는 Windows 개발자/QA다. 하지만 제품에 임베디드 전용 필드를 강제하지 않는다.

사용자는 업무 A에 관찰 한 줄과 이미지를 남긴다. 다음 행동을 선택적으로 적는다. 다른 일을 하고 돌아와 업무 A의 마지막 기록·근거·다음 행동을 확인한다. 같은 업무에 다시 기록한 뒤 완료한다. 선택한 원문과 파일만 보고서로 내보낸다.

반드시 유지할 세 원칙:

1. **아무 분류 없이도 캡슐에서 즉시 기록할 수 있다.** 업무·프로젝트·태그·제목을 필수로 요구하지 않는다.
2. **타임라인이 중심이다.** ‘이어하기’를 이유로 메인 화면을 칸반·대시보드·챗봇으로 교체하지 않는다.
3. **이어하기는 맥락 열기다.** 디버거/IDE 상태 복원, 작업 시작 타이머, TODO 재열기와 혼동하지 않는다.

## 2. 완료할 화면과 명령

| ID | 화면/기능 | 구현 완료 조건 |
|---|---|---|
| F01 | 기존 캡슐 | 한 줄 유지, 저장 상태 분리, 연결 업무 표시, 입력·첨부 보존 |
| T01 | 하루의 흐름 | 날짜·보기 분리, 읽기 좋은 시간축, 기록 유형별 표시, 작은 이어하기 진입점 |
| W02 | 업무 맥락 패널 | 마지막 기록·원본 자료·다음 행동·전체 흐름·이어서 기록 |
| N01 | 다음 행동 편집 | 선택적 한 줄, 변경 이력·출처·복구, 완료 상태와 일관성 |
| R01 | 하루 정리 | 명시적 기록/파일 선택, 원문 연결, 미리보기와 실제 출력 일치 |
| O02 | 샘플 흐름 | 운영 DB와 분리된 샘플 하루 및 재개 시나리오 |

화면마다 동일 업무/기록은 동일 ID를 사용한다. W02는 새로운 독립 업무 저장소가 아니다.

## 3. F01 — 캡슐을 무겁게 만들지 않고 업무 연결

### 3.1 외형 하드 게이트

- 가시 표면 기본 520×52 DIP, 반경 26 DIP. 일반 입력으로 높이를 늘리지 않는다.
- OS 제목표시줄·최소화/최대화/X 버튼·별도 브랜드 줄·큰 저장 행은 없다.
- 짙은 청록–슬레이트 표면, 밝은 글자, 기존 벡터 아이콘. 한 줄 안에 기능 아이콘을 계속 추가하지 않는다.
- 보조 패널은 동시에 하나만. 최근 기록/TODO는 캡슐 포함 가시 높이 240 DIP 이내, 긴 메모/첨부는 320 DIP 이내에서 내부 스크롤.
- 패널을 접으면 실제 창 경계도 축소한다. 투명한 큰 영역이 타 앱 클릭을 막지 않는지 OS에서 확인한다.
- 기존 상단 고정·이동·패널 유지·트레이·단축키 설정은 보존한다. 옛 세로창의 저장된 높이는 복원하지 않는다.
- 새 기능 때문에 캡슐의 폭을 계속 늘리거나 글자 전체를 축소하지 않는다.

### 3.2 입력과 저장 상태

`DraftText`, `DraftAttachments`, `DraftWorkItemId`, `SaveState`, `StatusMessage`를 개념상 구별한다. 기존 이름과 구조로 대응해도 된다.

- 한 줄 Enter/인라인 기록, 긴 메모 Enter 줄바꿈·Ctrl+Enter 기록. 실제 IME 조합 확정 Enter는 저장하지 않는다.
- TextBox.Text에 ‘09:11 기록됨’, ‘저장 중’, placeholder를 넣지 않는다.
- 성공 상태는 caret·선택·복사 대상이 아닌 별도 표시다. 사용자가 다시 입력하면 즉시 사라진다.
- 성공 전 입력/첨부를 지우지 않는다. 실패 시 짧은 오류 한 번과 재시도를 제공한다.
- 유효한 텍스트 또는 첨부가 없으면 저장 불가. 사진만 첨부하면 저장 가능하다.
- 이미지를 실제 썸네일로 보여준다. PNG라는 파일명을 표시한 것으로 완료하지 않는다.

### 3.3 연결 업무를 고르는 경로

상시 도구 아이콘을 늘리지 않고 기존 TODO 패널과 업무 상세를 사용한다.

- TODO 행 제목 클릭 → W02 업무 맥락 열기. 왼쪽 체크 클릭 → 완료. 두 동작을 분리한다.
- W02의 `이어서 기록` → 캡슐 열기·입력 포커스·연결 업무 명시.
- 일반 기록의 더보기/상세 `업무 연결` → 미완료/최근 업무 선택 또는 작은 `새 업무` 입력. 연결 해제도 제공한다.
- 캡슐 로고 메뉴의 `연결 업무 선택`도 키보드로 접근 가능하게 한다.
- 업무 선택 없는 메모는 즉시 저장한다. 시간 근접성·파일명·현재 열린 창으로 자동 연결하지 않는다.

연결된 경우 기존 입력 슬롯의 왼쪽에 최대 88 DIP의 짧은 업무 칩(가능하면 이슈 번호, 없으면 짧은 제목)을 표시한다. 입력부와 버튼이 겹치지 않게 Grid로 배치하고 전체 너비는 유지한다. 클릭/키보드로 전체 이름, 변경·해제를 볼 수 있게 한다. 작은 칩의 X만을 유일한 해제 경로로 만들지 않는다.

### 3.4 초안의 업무를 몰래 바꾸지 않는다

- 비어 있는 초안에서 업무 A를 이어서 열면 DraftWorkItemId=A로 지정한다.
- 기록 시작 후에는 해당 초안이 연결 업무 ID를 소유한다. 메인에서 업무 B를 클릭했다는 이유로 초안 A를 B에 붙이지 않는다.
- 내용/첨부가 있는 초안 상태에서 다른 업무의 `이어서 기록`을 누르면 작은 선택 UI를 표시한다: `기존 초안 계속`, `이 초안을 새 업무에 연결`, `취소`.
- 새 업무 연결은 사용자가 선택한 경우에만 기존 본문/첨부를 그대로 유지하여 변경한다. 원치 않은 자동 저장·초안 삭제·숨은 초안 복제는 없다.
- 같은 업무 선택이면 불필요한 확인창을 띄우지 않는다.
- 저장 성공 뒤 같은 세션에서는 연결 칩을 유지할 수 있다. 새 빈 세션/재시작은 미연결로 시작한다. 복구된 실제 초안은 원래 업무 연결도 복구한다.
- 완료/취소된 업무에 이미 작성 중인 초안은 지우지 않는다. 상태를 알려주고 연결을 유지한 추가 기록 또는 명시적 변경을 허용한다. 그것만으로 업무를 다시 열지 않는다.
- 외부 앱 클릭·패널 닫기·숨기기는 초안과 그 연결을 변경하지 않는다.

## 4. W02 — ‘마지막 기록 + 근거 + 다음 행동’ 한 화면

### 4.1 정보 순서

1. 업무명, 선택적 이슈 번호, `현재 진행 중/완료/취소` 상태.
2. `다음 행동` 블록. 텍스트 없으면 `다음 행동 남기기` 한 줄만.
3. `마지막 기록` — 가장 최근 일반 메모의 날짜·시각·원문 미리보기와 `원문 보기`.
4. `관련 자료` — 연결된 비삭제 기록에서 최근 첨부 최대 3개 + 전체 보기.
5. 해당 업무의 최근 기록 3개 및 `전체 흐름`.
6. 주요 행동 `이어서 기록`, 보조 `보고에 담기`, 더보기의 완료/취소/다시 열기.

제목/메모가 없으면 추정 내용을 만들지 않는다. ‘마지막 확인 사실’ 대신 `마지막 기록`이라고 쓴다. 첨부를 자동으로 ‘검증된 증거’ 또는 ‘중요 자료’로 분류하지 않는다.

### 4.2 자료 선택 규칙

- 마지막 기록: 이 업무에 연결된 휴지통 제외 일반 메모를 `(occurred_at, seq)` 내림차순으로 고른다. 생성/완료 이벤트가 마지막 메모를 밀어내지 않는다.
- 관련 자료: 해당 업무의 비삭제 기록 첨부를 최근 순으로 표시, 같은 attachment_id는 한 번만. 각 자료에 출처 메모로 가는 경로를 제공한다.
- 시각이 같으면 기존 순서 식별자로 안정 정렬한다. 표시와 전체 타임라인의 날짜 기준을 일치시킨다.
- 업무 맥락은 여러 날짜를 포함한다. 패널에 `이 업무 전체 기록 · 현재 상태`를 표시한다. 과거 날짜 타임라인 옆에서 오늘 상태를 당시 상태처럼 보여주지 않는다.
- 마지막 메모가 없으면 `아직 이 업무에 남긴 기록이 없어요`. 첨부 없으면 빈 영역을 크게 예약하지 않는다.
- 파일 누락은 해당 파일 문제만 표시한다. 업무 전체 열기를 실패시키거나 다른 파일까지 숨기지 않는다.
- 링크/파일/외부 프로그램은 사용자가 명시적으로 눌렀을 때만 연다. `이어서 기록`은 외부 프로그램 실행 명령이 아니다.

### 4.3 진입·복귀

하루 화면의 `이어서 할 일`, TODO 행 제목, 업무 배지, 업무별 목록에서 동일 업무 패널로 들어간다. `전체 흐름`은 기존 보기의 해당 업무 필터/전체 날짜 범위를 사용하고 범위를 표시한다. 뒤로 가면 이전 날짜·필터·스크롤을 복원한다.

기본 상세 너비는 352 DIP. 중앙 가용폭이 560 DIP보다 작아지면 상세를 352 DIP 내외의 닫을 수 있는 오버레이로 전환한다. 과도하게 작은 창에서는 작업 영역에 맞춘다. 상세가 없는 상태에는 빈 열을 남기지 않는다.

## 5. N01 — 다음 행동의 규칙을 고정한다

### 5.1 사용자 경험

- 한 업무에 현재 다음 행동은 최대 하나. 최대 200자, 필수 아님.
- W02에서 `다음 행동 남기기/수정` → 한 줄 입력 → 저장. Enter 저장은 해당 입력과 IME 규칙에 한정한다. 취소는 원래 값 유지.
- 공백은 새 행동으로 저장하지 않는다. 기존 행동의 제거는 명시적인 `지우기`로 처리한다.
- 일반 메모 메뉴의 `다음 행동으로 표시`는 작은 편집 UI를 연다. 원문을 제안값으로 채우되 저장 확정 전 필드를 변경하지 않는다.
- 원문이 200자를 넘으면 사용자가 줄여 저장하게 한다. 몰래 잘라 저장하거나 요약하지 않는다.
- 메모에 연결 업무가 없으면 업무를 고르거나 만들 수 있게 한다. ‘다음 행동으로 표시’ 자체를 새 TODO 자동 생성으로 해석하지 않는다.
- 다음 행동 저장 때문에 원문 메모 본문·최초 기록 시각을 바꾸지 않는다.

### 5.2 최소 데이터 계약

실제 스키마를 조사하고 동등 필드가 있으면 재사용한다. 아래는 요구되는 정보이지 SQL을 그대로 복사하라는 명령이 아니다.

```text
WorkItem 현재 투영:
  next_action_text?           사용자 입력, 1~200자
  next_action_source_entry_id? 선택적으로 원문 참조
  next_action_source_revision? 원문 당시 버전/해시 식별
  next_action_updated_at_utc?
  기존 version / 현재 상태

변경 이력:
  업무 ID, 변경 전/후 값 또는 복원 가능한 스냅샷,
  changed_at_utc, request_id, 원문 참조, 변경 이유(set/update/clear/completion)
```

기존 work_item_revisions에 담을 수 있으면 사용한다. 동등한 이력이 없을 때만 작은 전용 이력 저장을 추가한다. 범용 이벤트 소싱/그래프/새 작업관리 엔진은 만들지 않는다. 버전 충돌과 동일 요청 재시도는 기존 방식으로 처리한다.

- 조회만으로 다음 행동의 수정 시각을 바꾸지 않는다.
- 원문 메모 편집이 다음 행동을 자동 변경하지 않는다. 사용자가 확정한 스냅샷이다.
- 원문 삭제·연결 변경 시 자동으로 다른 업무에 다음 행동을 이동하지 않는다. 출처를 이용할 수 없는 경우 상태를 표시하며 이력·사용자 입력은 보존한다.
- 다음 행동은 업무시간/일시정지 상태가 아니다. 별도의 running/paused 타이머 상태를 추가하지 않는다.

### 5.3 완료·재열기와의 관계

- 업무 완료/취소 시 현재 활성 다음 행동은 비운다. 이전 값은 같은 트랜잭션의 이력에 남긴다.
- 완료·취소로 활성 다음 행동을 비운다고 과거 기록·첨부를 지우지 않는다.
- 다시 열어도 옛 다음 행동을 자동으로 활성화하지 않는다. `이전 다음 행동 사용`을 선택한 경우에만 복원하며 새 변경 이력을 남긴다.
- 완료된 업무의 일반 메모 추가는 허용하되, 다음 행동을 새로 활성화하려면 먼저 명시적으로 업무를 다시 열게 한다.
- 완료 실패 시 업무 상태와 다음 행동·이력이 함께 원상태여야 한다.
- 업무 완료에 결과 한 줄이나 근거 첨부를 필수로 요구하지 않는다.

### 5.4 과거 날짜 정확성

과거 날짜의 상태와 다음 행동은 현재 work_items 행만 읽어서 만들지 않는다. 기존 생명주기 이벤트와 다음 행동 변경 이력을 이용해 표시 시간대의 날짜 종료 시점(오늘은 현재) 상태를 계산한다.

이력 시작 전에는 `당시 다음 행동 기록 없음`으로 처리한다. 새 필드의 현재 값을 과거 날짜에 소급해서 채우지 않는다. 백업/복원과 보관 정책에 새 필드·이력을 포함한다.

## 6. T01 — 메인 화면을 ‘업무 흐름’으로 정돈

### 6.1 정보 구조와 기본 레이아웃

- 전역 탐색: `하루의 흐름`, `할 일`, `검색`, 아래 `설정`.
- 날짜: 이전/선택 날짜/다음/오늘. 날짜와 보기 탭을 같은 탐색 계층에 섞지 않는다.
- 보기: `시간순 / 파노라마 / 업무별`을 같은 위치에 고정.
- 상단 오른쪽 `하루 정리`. 미구현 버튼을 성공처럼 표시하지 않는다.
- 작은 집계와 `이어서 할 일 N` 진입점 하나. 요약 카드 3~6개를 타임라인 위에 만들지 않는다.
- 기본 화면은 시간순. 과거를 보고 있는데 새 메모가 생겼다고 날짜/스크롤을 강제로 변경하지 않는다.

배치의 기본 설계값(DIP):

```text
메인 초기: 1280×820 안에서 현재 작업 영역에 맞춤
좌측 탐색: 168, 외부 여백: 24
상단 콘텐츠: 96~136 이내(제목·날짜·탭·작은 진입점)
본문: 시간열56 / 노드열24 / 기록열 가변
기록 읽기 영역: 최대720, 전체 흐름 묶음 최대800
상세: 선택할 때만352; 중앙560 미만이면 오버레이
좁은 폭(<1000): 탐색56 레일, 실제 이름 툴팁·접근성 이름
```

수치는 기본 설계값이며 실측 제품 성능이나 보편적 UX 표준이 아니다. 긴 한글/큰 배율에서 잘림을 피하기 위한 내용 스크롤과 적응 배치를 사용한다. 화면 전체를 Viewbox로 축소하지 않는다.

### 6.2 이어서 할 일

상단에는 `이어서 할 일 N` 한 줄 진입점만 상주한다. 클릭하면 최대 3개 업무의 제목·다음 행동 한 줄을 보여주고 `전체 할 일`로 이동할 수 있게 한다. 상세는 W02로 연결한다. 열린 목록을 제외하면 큰 상시 패널은 없다.

대상: **현재 진행 중인 전체 업무**, 날짜 선택과 독립. `현재 진행 중`을 명시한다. 다음 행동 있는 업무를 먼저, 그 안에서는 최근 사용자 내용 변경 순으로 정렬한다. 내용 변경은 업무 생성/일반 연결 메모의 기록 시각/사용자 다음 행동 변경이다. 단순 조회·패널 열기·화면 전환으로 순서를 바꾸지 않는다. 동률은 안정 ID 순서. 사용자 의도나 중요도를 추정하지 않는다.

다음 행동 없는 업무도 `다음 행동 미등록`으로 접근 가능해야 한다. 완료/취소 업무를 이 목록에 남기지 않는다.

### 6.3 시간순 카드

- 짧은 메모: 최소높이44, 내용 패딩12~16, 본문 미리보기2~3줄. 내용에 맞춰 높이 결정.
- 카드 최대폭720. 한 줄 문장을 창 너비 끝까지 늘어뜨리지 않는다. 같은 영역의 왼쪽 기준선은 맞춘다.
- 기본 글자14, 본문 줄높이20~22, 제목15~16 Semibold, 메타12~13.
- 첫 줄을 제목으로 썼으면 본문에 같은 문장을 다시 쓰지 않는다. 저장 원문은 변경하지 않는다.
- 원문 제목 없는 이미지 단독 기록은 `이미지 기록` 같은 중립 표시. 자동 파일명을 큰 제목과 본문에 반복하지 않는다.
- 대표 이미지: 가용폭 안에서 최대320×180 DIP의 미리보기, 비율 유지/전체 맞춤. 긴 화면캡처의 중요한 부분을 몰래 잘라내지 않는다. 클릭 확대 제공.
- 일반 파일: 아이콘·원래 이름·크기, 작은 타일. 모든 이미지를 48px 파일 아이콘처럼만 표현하지 않는다.
- 첨부 최대3개 우선, 나머지 +N. 실제 데이터로 표시하며 깨진/없는 이미지 대체 상태를 구분한다.
- 업무 배지는 연결된 기록에만. 클릭은 W02. 긴 이름은 말줄임+전체 이름 접근.
- 생성/완료/재열기/취소는 별도 작은 사건 행. 생성 중립, 완료 체크+성공색, 재열기 아이콘+문구, 취소 텍스트. 동일 상태를 색만으로 표현하지 않는다.
- 연결선은 시간 순서를 보조한다. 같은 업무라고 기록의 실제 순서를 바꾸지 않는다.
- ‘업무 미연결 / 그룹’을 시간순 보기의 큰 카드로 넣지 않는다.
- 선택 강조는 얇은 윤곽+은은한 표면. 모든 카드에 다중 그림자·과도한 반경·네온을 사용하지 않는다.

### 6.4 상태와 파노라마

0개는 짧은 안내와 `첫 기록 남기기`, 별도 `샘플 하루 보기`. 1개는 시각·노드·기록1개만; 가짜 통계나 설명용 카드로 채우지 않는다.

기존 파노라마의 날짜·필터·선택을 보존하고 업무 배지/같은 Entry 상세 연결을 맞춘다. 파노라마가 없으면 그 사실을 보고한다. 이번에 새 시각화 엔진을 작성하지 않는다. 존재하는 미니맵의 하루 전체·빈 구간·밀집 항목 접근을 회귀 검수한다. 기록 간격을 근무시간으로 변환하지 않는다.

## 7. 시각 자산·공통 컴포넌트 계약

캡슐은 어두운 유리풍, 본창은 밝은 업무용 표면으로 유지한다. 둘 다 동일 아이콘·상태 의미·타이포 계층을 사용하되 배경에 맞는 강조색 대비를 달리한다.

- 본창 바탕 #F5F7F9, 표면 #FFFFFF, 본문 #172B32, 보조 #53676D.
- 본창 주요 행동 #126B65, 옅은 강조 #E5F3F1. 캡슐 강조 #55CFC7를 밝은 바탕의 작은 글자로 무조건 재사용하지 않는다.
- 캡슐 색·반경·패널 높이는 v2 유지. 글자까지 흐려지게 Window 전체 Opacity를 낮추지 않는다.
- 간격4/8/12/16/24/32, 기본 컨트롤 높이32~36, 콘텐츠 카드 반경12, 얇은 경계 #DCE5E8.
- 라이선스 확인된 기존 로컬 벡터 한 세트. 원격 아이콘/폰트/새로운 캐릭터·브랜드 제작은 없다.
- 기본/hover/pressed/disabled/선택/키보드 포커스/저장 중/실패를 실제로 구현한다.
- 색/반경만 바꾼 후 디자인 완료라고 하지 않는다. 화면 계층·정보 폭·이미지 가독성·상태 분리를 함께 적용한다.

`03_VISUAL_CONTRACT.md`와 `design_tokens.json`을 함께 따른다. JSON은 명세 보조 자료이며 새 런타임 테마 시스템을 만들라는 뜻이 아니다. 이미 있는 ResourceDictionary와 실제 제품 컨트롤을 수정한다.

개발 프리뷰는 보조 수단이다. 프리뷰만 예쁜 별도 컴포넌트를 만들거나 다음 단계에서 사용자 승인을 기다리지 않는다.

## 8. 완료와 근거 — 자동 보존과 자동 공유는 다르다

업무 체크는 기존 완료 서비스를 사용한다. 상태 변경과 완료 이벤트, 다음 행동 비우기·이력 저장은 같은 성공/실패 단위다. 동일 요청·빠른 반복 클릭·두 창 동시 명령으로 중복 완료 이력이 생기지 않는다.

- 성공 후 활성 TODO에서 제거, 타임라인에 완료 이벤트 표시, 실행 취소 경로 유지.
- 업무에 연결된 원문/첨부는 그대로 보존하고 완료된 업무 상세에서 확인 가능.
- 완료 클릭마다 첨부 원본을 복사하여 별도 거대 패키지를 생성하지 않는다. 관계/이력으로 조회한다.
- 완료한 업무에 결과를 추가하려면 일반 연결 메모로 선택적 입력한다. 필수 보고서 모달은 없다.
- 완료 이력과 당시 자료를 현재 업무명/현재 첨부만으로 덮어쓰지 않는다. 기존 제목 스냅샷과 revision을 보존한다.
- 실제 자료가 없으면 ‘근거 첨부 없음’. 단순 체크를 시험 성공이나 문제 해결로 바꿔 쓰지 않는다.
- 완료 후 ‘보고에 담기’는 선택 화면 진입이지 외부 업로드가 아니다.

## 9. R01 — 선택한 원문과 자료로 보고

### 9.1 화면과 사용 흐름

`하루 정리` → 날짜/표시 시간대 확인 → 포함할 기록 선택 → 파일 선택 → 미리보기 → 텍스트 복사 또는 기존 Markdown+첨부 ZIP 저장.

넓은 화면은 왼쪽 선택 목록/오른쪽 읽기 전용 미리보기. 좁으면 `선택 / 미리보기` 전환. 상단에 기간과 선택 개수, 하단에 실제 실행 버튼을 둔다. 선택0이면 출력 실행 불가.

첫 진입은 내용·파일 모두 미선택. W02의 `보고에 담기`는 그 업무로 목록을 필터링할 뿐 과거 메모/파일을 자동 선택하지 않는다. 필터는 명확히 보이고 제거 가능하다.

### 9.2 선택 단위와 포함 범위

- 선택 가능한 본문 단위는 일반 메모, 생명주기 이벤트, 명시적 다음 행동 스냅샷이다.
- 업무 그룹 체크는 화면에 표시한 **해당 날짜의 항목 N개 선택**임을 레이블/개수로 알리고 그 항목만 선택한다. 숨은 과거 기록을 선택하지 않는다.
- 다음 행동은 별도 체크 항목이며 초기 미선택. 과거 날짜는 해당 날짜 종료 시점의 이력에서 선택한다.
- 파일은 본문 선택과 별도로 기본 미포함. 선택한 본문에 연결된 파일만 선택 가능하다. 부모 해제 시 자식 파일 선택도 해제한다.
- 과거 근거가 필요하면 `다른 날짜의 근거 추가`를 사용하여 해당 업무의 날짜가 표시된 기록을 명시적으로 추가한다. 자동 범위 확장은 없다.
- 과거 근거는 보고서의 `참고 기록(기간 밖)` 영역에 원래 날짜를 표시한다. 오늘 수행한 업무처럼 합치지 않는다.
- 미선택 기록의 본문·파일명·이슈·다음 행동·첨부 경로를 결과나 manifest에 포함하지 않는다.
- 내보내기는 백업이 아니다. 전체 DB, 초안, 삭제 기록, 전체 revision, 설정/로컬 절대경로를 끼워 넣지 않는다.

### 9.3 보고서 내용

기본 섹션은 `완료한 일 / 남은 업무의 기록 / 다음 행동 / 참고 기록`이다. 비어 있는 섹션은 숨긴다. 기계적으로 분류 불가능한 일반 메모는 `남긴 기록`으로 표시한다.

‘관찰’, ‘원인’, ‘성공’ 같은 해석은 원문에서 사용자에게 확인된 문장 없이 만들어내지 않는다. 메모 제목/본문을 길이 제한 때문에 줄이면 생략 표시와 원문 접근을 제공한다. 앱 안의 각 출력 항목은 실제 Entry/Revision 또는 다음 행동 이력으로 돌아갈 수 있어야 한다.

완료/진행 상태는 보고 범위 끝 시점의 생명주기 이벤트로 계산한다. 다음 날 다시 열린 일이 전날 완료 기록을 삭제하게 하지 않는다. 보고 UI에 현재 상태와 과거 상태가 함께 있으면 레이블로 구분한다.

사용자가 보고 제목을 바꾸거나 내용을 별도로 편집하는 기능을 이미 갖고 있다면 수동 편집임을 구분한다. 이번에 복잡한 보고서 에디터를 새로 만들지 않는다.

### 9.4 미리보기와 실제 출력 일치

미리보기 시점에 선택 항목의 원문 버전·메타데이터·첨부 ID/해시를 고정한 `ReportSnapshot`에 해당하는 객체를 만든다. 복사와 ZIP은 같은 스냅샷을 소비한다.

- 미리보기 뒤 원문·연결·다음 행동이 바뀌면 `내용이 변경됐어요. 미리보기를 갱신하세요`를 표시하고 갱신 전 최종 출력을 막는다. 조용히 새 원문으로 바꾸지 않는다.
- 파일 누락/변경/읽기 실패 시 성공으로 표시하지 않는다. 사용자가 해당 파일 선택을 해제하거나 재시도할 수 있게 한다.
- 최종 저장은 임시 결과 생성·검증 후 확정. 취소나 실패해도 원본과 선택은 보존한다.
- ZIP은 report.md, attachments/, 최소 manifest. 링크는 상대 경로, 안전한 파일명, 선택 파일만. 파일명 충돌과 경로 탈출을 처리한다.
- 외부 수신자가 FlowNote 없이 본문을 읽을 수 있어야 한다. 앱 안 원문 연결 기능이 외부 문서의 필수 의존성이 되면 안 된다.
- 자동 Jira 등록·메일 전송·클립보드 성공 위장은 없다. 복사는 사용자가 누르고 실제 성공한 경우에만 표시한다.

## 10. 구조·Migration·성능

현재 프레임워크/SDK/패키지를 조사한 후 유지한다. 프로젝트가 이미 WPF라면 View/ResourceDictionary/ViewModel/서비스 경계를 따르고, 다른 구조라면 구현을 맞추되 앱을 이전하지 않는다.

권장 서비스 책임(동등 기존 코드 우선):

```text
WorkContextQuery: 마지막 기록/관련 자료/현재 다음 행동 조회
WorkLinkCommand: 일반 메모의 업무 연결/해제 + revision
NextActionCommand: 다음 행동 변경/비우기 + history + version
ReportBuilder: 선택한 소스 → 결정적 ReportSnapshot
기존 Entry/WorkItem/Attachment/Backup/Export 서비스: 유지·최소 확장
```

- DB/파일/이미지 작업은 UI 스레드를 막지 않는 기존 실행 경로를 사용한다. 새 화면마다 DB 연결과 전체 사본을 따로 두지 않는다.
- 일반 메모 재연결만 허용한다. 과거 완료 이벤트의 업무 ID를 임의로 바꾸지 않는다.
- 연결 변경은 내용·최초 기록 시각을 유지하고 revision에 이전 업무를 남긴다.
- 원본 첨부는 앱 사본, UI는 작은 썸네일. 데이터 재정렬 때문에 매번 원본 이미지를 다시 열지 않는다.
- 새 query에는 적절한 인덱스/제한 범위를 사용한다. 로딩 중/결과 없음/오류를 구분하고 늦은 이전 query 결과가 선택 업무를 덮지 않게 한다.
- 사용자가 빠르게 A→B로 전환해도 B 화면에 A의 기록/다음 행동이 뒤늦게 나타나면 안 된다.
- 운영 DB의 기존 스키마와 동등 필드를 먼저 확인한다. 반복 실행 가능한 최소 migration과 이전 버전 데이터 검증을 추가한다.
- 개발 테스트는 복사/임시 데이터로 한다. 검증 전 운영 DB를 임의 업그레이드하거나 덮어쓰지 않는다.
- 새 빌드의 첫 실제 업그레이드는 검증된 안전 사본·호환 검사·실패 복귀 절차를 갖춘다. 이를 확보하지 못하면 운영 DB에 적용하지 말고 차단 사유를 보고한다.
- Migration 실패를 새 빈 DB 생성으로 처리하지 않는다. 기존 백업/복원에 다음 행동·출처/이력을 포함하고 실제 재검수한다.
- 출처 ID/해시는 참조·무결성 수단이지 법적 증거성/위조 불가능성 보장이 아니다.

성능은 실제 동일 환경 전후로 기록한다. 기존 목표를 유지하고, 신규 업무 맥락 열기는 10,000개 기록 fixture에서 p95 500ms 이내를 초기 목표로 삼는다. 캡슐 호출 p95 200ms, 저장 UI 반영 p95 300ms, 유휴60초 평균 CPU1% 이하는 목표이며 실적이 아니다. Working Set/Private Bytes는 캡슐 단독·메인 열림을 구분해 측정한다. 숫자를 줄이려고 필수 기능을 끄거나 캐시를 지운 순간만 측정하지 않는다.

## 11. 실제 화면과 사용자 검증

`02_ACCEPTANCE_TESTS.md`를 기능/시각/환경으로 나눠 채운다. 기존 46개 또는 현재 실제 테스트 개수는 baseline으로 기록하되 새 요구가 검증됐다는 뜻으로 확대하지 않는다.

- `RenderTargetBitmap`과 smoke는 보조 렌더/실행 검수다. 실제 OS 창·IME·포커스·투명 영역·DPI를 단독으로 입증하지 않는다.
- 전체 OS 캡처 원본과 필요 시 읽기용 크롭을 구분한다. 배율·창 크기·빌드/커밋·demo 여부를 캡처마다 기록한다.
- 개발 프리뷰와 실제 제품은 같은 컨트롤을 사용한다. 생성 이미지/HTML/정적 그림을 실행 화면으로 제출하지 않는다.
- 일반 문서와 어두운 편집기 위의 캡슐을 모두 검수한다. 회사 원문이나 개인 정보가 함께 찍히지 않게 격리된 자료만 사용한다.
- 100%와 150% 이상 한 배율, 좁은 창, 긴 한글, 빈/한 개/혼합/밀집 기록, 실패 상태를 실제 가능한 환경에서 검사한다. 가짜 확대 캡처를 DPI 검수로 부르지 않는다.
- 초보자 사용성·구매 의향은 실제 참여자 없이 PASS하지 않는다. 테스트 과제/관찰 양식만 납품하고 HUMAN NOT RUN으로 남긴다.

사용성 검증 과제: 설명 없이 메모1개 기록 → 이미지를 첨부 → 업무에 연결 → 다음 행동 지정 → 다른 날 다시 열어 원문 찾기 → 완료 → 보고에 파일 하나만 포함. 키보드 팁을 아는 숙련 agent의 성공을 초보자 성공으로 바꾸어 쓰지 않는다.

## 12. 무인 실행 계획

### P0 — 조사와 회귀 방지

저장소·현재 변경·빌드·화면·실제 서비스/스키마를 확인한다. baseline 테스트·OS 캡처, 요구-코드 매핑, 충돌 대체 문서를 남긴다. ‘다음 단계 승인이 필요’라는 이유로 멈추지 않는다.

### P1 — 캡슐/공통 UI 결함 정리

성공 문구와 TextBox 분리, 이미지 미리보기, TODO 빈 패널/유지 상태, 버튼 역할을 수정한다. 실제 캡슐의52 DIP·포커스·초안을 먼저 회귀 확인한다. 공통 토큰과 대표 기록/사건 행을 제품에 적용한다.

### P2 — 데이터 연결과 다음 행동

기존 업무 연결을 정리하고 최소 migration·다음 행동 이력·완료 일관성·재연결을 구현한다. 고정 fixture로 삭제·편집·재열기·과거 시점·중복/실패를 테스트한다.

### P3 — 업무 맥락과 이어서 기록

W02를 실제 데이터에 연결하고 캡슐의 명시적 연결 칩/초안 전환을 완성한다. A/B 빠른 전환, 재실행, 완료된 업무의 초안, 연결 해제까지 검수한다.

### P4 — 하루 화면과 선택 보고

T01을 본 지침대로 정돈한다. 기존 파노라마/검색을 파괴하지 않는다. R01의 선택 범위·원문·과거 근거·동일 스냅샷 출력·민감 메모 제외를 끝까지 구현한다.

### P5 — 실제 시연/검수/납품

샘플 하루를 격리된 저장소에서 실제 서비스로 생성한다. 전날 기록→재시작→업무 재개→완료→선택 보고→내보낸 파일 확인을 수행한다. 최대3회의 시각 확인·수정 사이클을 거치되 반복 횟수로 합격을 대신하지 않는다. 기능 회귀가 있으면 먼저 수정한다.

각 단계는 내부 순서일 뿐 새 사용자 요청을 기다리는 중단점이 아니다. 가능한 자동 테스트와 실제 실행을 수행하고 안전한 다음 작업으로 이어간다. 새 기능 추가·대규모 리팩터링으로 범위를 넓히지 않는다.

동일 파일을 여러 하위 agent가 동시에 수정하지 않는다. 별도 검토자/테스터가 실제 있을 때만 역할을 나누고, 존재하지 않는 디자이너 승인·외부 사용자 검증을 꾸미지 않는다.

환경·권한 때문에 막힌 항목은 BLOCKED/NOT RUN으로 두고 안전하고 독립적인 작업을 계속한다. 실패한 종속 기능까지 완료 처리하지 않는다. 제한 없이 영구 반복하지 않는다. 세 번의 합리적인 시도 후에도 동일 차단이 있으면 원인·시도·필요 조건을 남긴다.

컨텍스트/세션 한계가 오면 `docs/product-v3/PROGRESS.md`에 정확한 다음 파일/테스트/명령과 상태를 남긴다. 런타임 밖의 자동 재개나 밤새 실행을 보장한다고 말하지 않는다.
