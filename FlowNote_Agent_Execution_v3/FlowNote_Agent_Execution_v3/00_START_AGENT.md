# 작업 에이전트 시작 프롬프트

아래 지시와 이 폴더 전체를 현재 FlowNote 저장소에 접근 가능한 에이전트에게 제공한다. 이 파일만으로 다른 첨부가 자동 전달되는 것은 아니다. 저장소의 강제 보안/권한 규칙을 변경하거나 우회하지 않는다.

---

당신은 기존 FlowNote의 제품 구현 책임자다.
이번 작업은 추가 기획이나 홍보용 목업 제작이 아니다.
현재 앱에서 다음 사용자 흐름을 실제로 완성하라.

한 줄/사진 기록 → 선택적인 업무 연결 → 다음 행동 한 줄
→ 나중에 마지막 기록·자료·다음 행동 확인
→ 같은 업무에 이어서 기록 → 완료 이력 보존
→ 선택한 내용과 근거만 보고에 담기.

먼저 실제로 읽어라.
1. 이 폴더의 01_MASTER_WORK_ORDER.md
2. 03_VISUAL_CONTRACT.md
3. 02_ACCEPTANCE_TESTS.md
4. fixtures/SCENARIO.md 및 scenario.json
5. references/README.md와 기준 이미지
6. 현재 저장소의 작업 규칙, 변경 상태, 진행 기록, 실제 코드·스키마

파일이 없으면 확인한 경로와 누락 항목을 보고한다.
자료를 읽거나 이미지를 보지 못했는데 확인했다고 가정하지 마라.

[우선순위 변경]
이번 V3가 상충하는 이전 UI/실행 지시를 대체한다.
- 캡슐 v2의 무제목표시줄 520×52 DIP 한 줄 외형은 유지한다.
- 이전의 ‘플로팅만 수정’은 이번에 해제한다.
- 메인 시간순, 업무 맥락, 다음 행동, 선택 보고를 이번 범위에 포함한다.
- U0 승인 대기/단계마다 사용자 호출은 하지 않는다.
- 내부 단계는 순서대로 진행하되 구현·검수·빌드까지 계속한다.
- 가격·체험판·결제·AI·자동 수집·새 프레임워크는 만들지 않는다.
충돌한 실제 문서와 대체 내용을 docs/product-v3/SUPERSEDED.md에 기록하라.

[작업 순서]
P0. 현재 코드/DB/빌드/화면 조사, 변경 보존, baseline 검수.
P1. 캡슐의 입력/성공 상태 분리와 실제 썸네일, 공통 UI 정리.
P2. 기존 업무·기록 연결, 다음 행동과 이력, 최소 migration 구현.
P3. 업무 맥락과 ‘이어서 기록’, 초안의 명시적 업무 연결 구현.
P4. 메인 타임라인 정돈, 원문·파일 선택 기반 보고 완성.
P5. 실제 end-to-end 시연, 회귀·시각 검수, 실행 빌드 제출.

[절대 후퇴하지 말 것]
- 세로 메모장/큰 상시 TODO 패널/Windows 제목줄로 캡슐을 되돌리지 않는다.
- ‘기록됨’이나 placeholder를 TextBox.Text에 넣지 않는다.
- 업무·태그·다음 행동을 일반 메모 저장의 필수항목으로 만들지 않는다.
- 화면에서 다른 업무를 클릭했다고 작성 중 초안의 업무를 몰래 바꾸지 않는다.
- 완료는 삭제가 아니다. 체크 한 번으로 완료하고 근거 없는 완료도 허용한다.
- 다음 행동은 최대 한 줄의 사용자 입력이다. AI가 추정하지 않는다.
- ‘이어서’는 기록과 자료를 여는 것이다. 타이머나 디버거 상태 복구가 아니다.
- 보고서에 미선택 본문·파일명·파일·과거 기록·초안을 몰래 포함하지 않는다.
- 기록 시각과 실제 작업시간을 혼동하지 않는다.

[개발 방식]
기존 프레임워크와 서비스, DB, 첨부 사본·초안·완료 이력을 보존한다.
운영 데이터에 합성 예시를 섞지 않는다.
새 필드는 실제 스키마를 조사하고 최소 migration으로 추가한다.
업무 완료·다음 행동 변경의 이력, 중복 요청·실패 복구를 테스트한다.
View에 DB 규칙을 넣거나 새 앱을 만들어 기존 앱을 수정했다고 하지 마라.

[디자인 검수]
‘더 고급스럽게’라고 임의 재해석하지 말고 시각 계약을 따른다.
캡슐은 작게, 메인은 읽기 좋은 시간축, 이미지는 보이는 썸네일로 만든다.
업무 맥락은 마지막 기록·관련 자료·다음 행동을 한 화면에 보여준다.
빈 상세 열, 긴 빈 카드, 중복 제목/파일명, 같은 무게의 버튼을 정리한다.
프리뷰와 제품은 같은 컴포넌트를 사용한다.
표본만 제출하고 승인을 기다리지 마라.

[실행·테스트]
실제 Windows 실행 → OS 캡처 → 명세와 비교 → 수정 사이클을 최대3회 수행한다.
RenderTargetBitmap/smoke만으로 IME·포커스·DPI·창 외곽까지 PASS하지 마라.
기존 테스트와 신규 검수를 실제 수행하고 증거 경로를 남긴다.
미실행은 NOT RUN, 환경/권한 차단은 BLOCKED다.
실제 참여자 없이 초보자 사용성이나 구매 의향을 통과했다고 하지 마라.

데이터 손실·보안 우회·권한 확대가 필요한 작업은 수행하지 않는다.
차단된 부분은 분리하고 안전한 독립 작업은 계속한다.
세션 한계가 오면 PROGRESS.md에 정확한 재개 지점을 남긴다.
실제 런타임 밖의 자동 재개나 무한 실행을 보장하지 마라.

[최종 결과]
개선된 소스와 실행 빌드, 실제 전후 화면,
기록→재개→완료→보고 시연, 선택한 자료만 담은 예시 ZIP,
테스트/성능 실측, 미검증·미해결 항목을 제출한다.

‘전략 이해’, ‘U0 완료, 다음은 U1’, ‘디자인 승인 대기’로 끝내지 마라.
구현한 범위와 검증한 범위를 분리하고,
유료 판매 성공이나 해자를 확보했다고 주장하지 마라.
