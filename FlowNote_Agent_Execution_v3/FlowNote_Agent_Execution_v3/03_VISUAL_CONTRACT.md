# V3 화면·상호작용 계약

역할: 주관적인 ‘프리미엄/세련됨’을 반복 요구하지 않고, 개발자가 같은 화면을 만들기 위한 배치·상태를 고정한다.
이 문서는 구현 전 설계 기준이며 승인된 실제 앱 화면이나 사용자 실험 결과가 아니다.

## 1. 기준 자료

- references/01_target_capsule.png: 사용자가 지정한 캡슐 형태의 목표. 외부 설명 문구/화살표/배경은 UI가 아니다.
- references/02_current_main.png: 개선 전 본창. 기능·데이터의 출발점이지 최종 디자인 기준이 아니다.
- references/03~06: 개선 전 캡슐의 TODO/빈/성공/입력 상태. 관찰 자료다.
- 과거 포스터의 모바일 프레임·AI·구독·멀티플랫폼 로고는 이번 구현 요구가 아니다.

## 2. 캡슐

```text
╭──────────────────────────────────────────────────────────────╮
│ F  [DEV-1234 ×] 관찰을 입력…   [기록] [영역] [첨부] [할 일] [시계]│
╰──────────────────────────────────────────────────────────────╯
```

위 텍스트는 아이콘 역할 설명이다. 실제 구조는 가시520×52, 내부 패딩12, 입력 가변, 기존 아이콘 슬롯 고정. 업무 칩은 선택한 때만 입력 슬롯 안에 최대88 폭으로 넣는다. 기록 슬롯은 빈 때 외형·포커스·히트테스트만 숨겨 타이핑에 전체 위치가 흔들리지 않게 한다.

- 입력 전: 기본 placeholder, 아래 공간 없음.
- 업무 연결: 작은 업무 칩과 입력. 미연결이면 칩 없음.
- 입력 중: caret/선택은 사용자 텍스트에만. 기본 높이 유지.
- 성공: TextBox의 값이 아니라 별도 비편집 상태. 1.5초 내 또는 새 입력 즉시 해제.
- 오류: 초안·첨부 유지, 작은 오류와 재시도. 여러 오류 문장 중복 금지.
- TODO: 작은 패널 하나, 최대3행 우선, 유지 ON/OFF가 시각·접근성 상태로 확인됨.
- 긴 입력/첨부: 기존 패널 하나로 전환. 캡슐과 패널에 두 편집기가 동시에 같은 초안을 덮지 않게 한다.

여러 화면으로 이동해도 캡슐의 명시적인 연결 칩을 숨기지 않는다. 완료된 업무에 작성 중인 경우 칩/패널에 완료 상태를 표시하고 데이터를 보존한다.

## 3. 메인 시간순

```text
┌─────────────────────────────────────────────────────────────────┐
│탐색  │ 오늘의 흐름                  날짜 이동         하루 정리 │
│      │ 시간순 | 파노라마 | 업무별       이어서 할 일 2          │
│      │ 기록 · 완료 · 첨부                                      │
│      │                                                        │
│      │ 09:12  ● 조건 B에서만 재현됨       [DEV-1234]            │
│      │        │ [실제 이미지 미리보기] [로그 타일]               │
│      │ 09:20  ✓ 재시작 오류 확인 완료                           │
│      │                                                        │
└─────────────────────────────────────────────────────────────────┘
```

상세 미선택일 때 빈 오른쪽 열 없음. 기록 전체가 너무 넓어지지 않도록 읽기 영역 최대800(시각·노드 포함), 카드 최대720. 남는 공간을 가짜 통계로 채우지 않는다.

상단에는 이어하기를 위한 **하나의 작은 진입점**만 넣는다. 3개의 큰 업무 카드를 기본으로 깔아 타임라인을 아래로 밀지 않는다.

기록 유형별 밀도:

| 유형 | 외형 | 상호작용 |
|---|---|---|
| 텍스트 | 간결한 카드, 제목/본문 중복 없음 | 원문 상세·업무 연결·다음 행동으로 표시 |
| 이미지 | 실제 이미지 최대320×180, 비율 유지 | 확대, 원문/연결 확인 |
| 일반 파일 | 파일명·크기·아이콘 타일 | 명시적 열기·위치/원문 확인 |
| 생성/완료/재열기 | 낮은 사건 행, 텍스트+아이콘 | 관련 업무와 당시 이벤트 |
| 업무 미연결 | 별도 그룹 카드 없음 | 더보기에서 연결 가능 |

시간순은 실제 시간순, 업무별은 묶음, 파노라마는 시간 분포다. 탭만 바꾸고 서로 다른 의미를 같은 레이블로 부르지 않는다.

## 4. 업무 맥락 패널

```text
┌─────────────────────────────────────┐
│ 취소 후 재시작 오류 확인        닫기 │
│ DEV-1234 · 현재 진행 중             │
│                                     │
│ 다음 행동                    수정   │
│ 펌프 OFF와 초기화 순서를 비교한다.   │
│                                     │
│ 마지막 기록 · 9월14일 09:18         │
│ UART 마지막 출력 확인 필요. 원문 보기│
│                                     │
│ 관련 자료                           │
│ [이미지] [sample-uart.log]           │
│                                     │
│ 최근 기록 …             전체 흐름   │
│                                     │
│ [이어서 기록]       보고에 담기      │
└─────────────────────────────────────┘
```

- 다음 행동이 없으면 큰 빈 박스 대신 `다음 행동 남기기` 한 줄.
- 출처/자료 없는 경우 명확한 작은 안내. AI 요약/중요도 점수 없음.
- ‘보고에 담기’는 해당 업무로 선택 화면을 필터링한다. 전체 기록이 자동 공유되지 않는다.
- 기본352 폭. 중앙 여유가 없으면 오버레이. Esc는 먼저 현재 작은 편집/팝오버를 닫고 입력을 보존한다.
- 최근3개는 전체 데이터가 아니다. 전체 흐름으로 모든 기록에 접근한다.

## 5. 보고 선택과 미리보기

```text
┌──────────────────────────────────────────────────────────────────┐
│ 하루 정리 · 9월15일 · 표시 시간대        선택2 · 파일1            │
├───────────────────────────────┬──────────────────────────────────┤
│ 선택할 원문                   │ 미리보기                         │
│ □ 업무 A의 당일 항목 2개      │ 제목 / 날짜 / 완료 또는 남긴 기록│
│   □ 09:10 시험 메모           │ 선택된 원문만 표시                │
│   □ 09:20 완료 이벤트         │ 원문 보기                         │
│ □ 기간 밖 근거 추가           │ 포함 파일                         │
│   □ 9월14일 09:18 로그 관찰   │ [선택한 이미지]                   │
│      □ 사진  □ 로그 파일      │                                  │
├───────────────────────────────┴──────────────────────────────────┤
│ 첨부는 기본 미포함                  텍스트 복사 · 패키지 저장    │
└──────────────────────────────────────────────────────────────────┘
```

첫 진입은 모두 미선택. 날짜 밖 기록은 별도 영역과 실제 날짜. 선택부와 결과부가 어느 시점 자료인지 명확하게 표시한다. 원문 변경 후 낡은 preview와 새 파일을 섞지 않는다.

## 6. 반응형·상태 테스트

- 0개/1개/혼합/밀집은 서로 다른 상태로 실제 화면을 확인한다.
- 본창1280×820은 출발점. 960×640 DIP와 사용 가능한 모니터의 높은 배율도 검사한다.
- 좁은 창은 열을 겹침/레일로 전환한다. 텍스트를 읽을 수 없게 전체 축소하지 않는다.
- 긴 제목/파일명은 말줄임하고 전체 접근 경로를 제공한다. 본문은 줄 수/스크롤로 처리한다.
- 작은 일반 텍스트는 충분한 명암 대비를 실제 렌더에서 확인한다. 색만으로 상태를 알게 하지 않는다.
- 키보드 포커스는 hover와 별개다. 보조 조작은 더보기나 키보드로도 접근한다.
- 실제 캡처 원본과 배율·창경계 메타데이터를 제공한다. 리사이즈한 PNG로 창 크기를 증명하지 않는다.

## 7. 완료 판정

기능 PASS + 실제 시각 계약 검수 + 알려진 제한 보고가 필요하다. 사용성/상품성은 사람의 별도 검증이다. 높은 자체 미적 점수로 인수 기준을 대체하지 않는다.
