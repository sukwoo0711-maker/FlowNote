# FlowNote Floating Capsule — 실행·구현 명세 v2.0

상태: 사용자 제공 두 번째 이미지를 기준으로 작성한 **플로팅 창 전용 변경 명세**다. 실행 앱·XAML을 구현하거나 성능을 측정한 결과물이 아니다.
대상: 기존 Windows/WPF FlowNote 프로젝트. 실제 경로·버전은 현재 저장소에서 확인한다.
이번 납품: 기존 플로팅 창을 한 줄 캡슐로 실제 교체한 빌드, 소스, OS 화면 캡처, 동작 검수 결과.

## 0. 가장 먼저 적용할 변경 계약

### 0.1 이전 디자인 지시를 합성하지 말고 교체한다

이번 문제는 기존 메모장 색을 바꾸거나 높이를 조금 줄여 해결하는 작업이 아니다.
**세로 메모장 → 가로 캡슐**로 플로팅 UI 구조를 교체한다. 기존 저장·업무 서비스는 보존한다.

| 기존 지시 | 이번에 적용할 지시 |
|---|---|
| 기본 360×500 또는 빈 상태 높이 280~340 DIP | 기본 캡슐 표면 520×52 DIP |
| 기본 메모 입력 80~96 DIP / 3~4줄 | 캡슐 안 한 줄 입력, 자동 줄바꿈 없음 |
| OS 기본 제목 표시줄 유지 가능 | 플로팅 창에만 기본 제목 표시줄·최소화/최대화/X 제거 |
| 상단 FlowNote·오늘·고정됨·접기·숨기기 | 로고 메뉴·한 줄 입력·작은 아이콘 조작으로 통합 |
| 흰색 표면·파란 직사각형 버튼 | 짙은 청록–슬레이트 캡슐·저대비 아이콘·절제된 청록 강조 |
| 아래 TODO와 추가 입력란 상시 배치 | 사용자가 연 작은 TODO 패널에서만 표시 |
| Enter 줄바꿈 / Ctrl+Enter 저장 | 한 줄 모드 Enter 기록; Ctrl+Enter도 유지; 긴 메모 모드는 별도 규칙 |
| 자동/수동 캡처 모두 제외 | 이번에 사용자가 직접 실행한 1회 영역 캡처만 추가 허용 |
| U0 표본 이후 승인 대기 | 이번 플로팅 범위 전체를 중간 승인 대기 없이 완주 |
| U1 뒤 U2/U3 전체 화면 재디자인 | 이번에는 플로팅만 수정; 메인은 연결·회귀 확인만 |

업데이트 대상: 기존 F01, 플로팅에 관한 디자인 토큰, UI 재작업서의 플로팅 절, 단계별 대기 규칙.
해당 문서에 `SUPERSEDED BY docs/FLOATING_CAPSULE_V2.md`를 표시하거나 충돌 문장을 교체한다.
새 문서를 아래쪽에 추가만 해서 상충하는 지시를 동시에 유효하게 두지 않는다.

**변경하지 않는 규칙:** 로컬 저장, 사용자 데이터·초안 보존, 첨부 사본, 기록/발생 시각 구별, 완료/재열기 이력·중복 방지, 기존 검색·타임라인·보고 기능, 회사 보안 정책.
앱 상단 고정은 회사 보안 화면보다 우선한다는 보장이 아니다. API·클라우드·자동 감시 기능은 추가하지 않는다.

### 0.2 참고 이미지의 역할

- `references/01_REJECTED_tall_notepad.png`: 폐기할 **UI 형식**. 재현 대상이 아니다.
- `references/02_TARGET_floating_capsule.png`: 이번 외형의 **우선 기준**. 가로세로 비율, 짙은 유리풍 표면, 한 줄 입력, 오른쪽 작은 조작, 아래에 붙는 작은 패널을 따른다.
- 두 이미지는 사용자가 제공한 원본이다. 두 번째는 목표 컨셉이지 실제 구현 완료 증거가 아니다.
- 그림 바깥의 ‘초경량 플로팅 로그 창’, 설명 화살표, 배경 그림, 영문 주석은 제품 UI에 넣지 않는다.
- 그림에 인쇄된 단축키를 현재 설정 확인 없이 등록하거나, 샘플 Jira 문구를 실제 데이터처럼 넣지 않는다.
- 참고 PNG를 창 배경으로 깔고 투명 버튼을 얹는 구현은 금지한다.

## 1. 구현할 제품 경험

**평상시 한 줄 → 적고 Enter → 시각과 함께 기록 → 필요한 경우에만 작은 패널 → 다시 한 줄.**

처음 뜨는 모습이 가장 중요하다. TODO가 없는데 300~500 DIP짜리 창이 뜨면 기능 테스트와 관계없이 이번 외형 요구는 실패다.
TODO가 있어도 기본은 캡슐이다. 항상 TODO를 보고 싶은 사용자는 ‘패널 유지’를 켤 수 있다.
‘앱을 다른 창보다 위에 둠’과 ‘아래 패널을 계속 펼쳐 둠’은 별도 설정이다.

기본 구조(문자는 실제 아이콘의 기능 설명):

```text
╭────────────────────────────────────────────────────────────────────────╮
│ F  지금 떠오른 것을 기록하세요…       [↵] [영역] [첨부] [☑ 할 일] [시계] │
╰────────────────────────────────────────────────────────────────────────╯
```

- 로고는 메뉴/이동 영역, 입력은 실제 TextBox다.
- 기록 버튼은 입력이 있을 때만 명확히 드러나는 작은 인라인 버튼이다. 별도 버튼 행은 없다.
- ‘영역’·‘첨부’·‘시계’는 설명용 표기다. 실제 캡슐에서는 통일된 벡터 아이콘으로 표시한다.
- 할 일은 체크리스트 아이콘+‘할 일’이라는 짧은 레이블을 유지해 발견 가능하게 한다.
- 부가 패널은 최대 하나만 열린다. 여러 패널이 세로로 계속 쌓이지 않는다.

## 2. 크기·배치 — WPF DIP 기준

아래 값은 이번 제품 설계값이다. 스크린샷의 물리 픽셀 측정값이나 일반 UX 표준이 아니다.

| 항목 | 값/규칙 |
|---|---|
| 캡슐 가시 표면 | 기본 W=520, H=52 DIP |
| 양끝 반경 | 26 DIP, 알약 형태 |
| 캡슐 내부 좌우 패딩 | 12 DIP |
| 로고 영역 | 28×32 DIP; 로고 자체 약 24~28 DIP |
| 아이콘 | 약 17~18 DIP, 버튼 클릭 영역 32×32 DIP |
| 입력 글자 | 13 DIP, 세로 가운데, 한 줄 |
| 입력 배경 | 투명, 기본 TextBox 직사각형 테두리 없음 |
| 바깥 투명 여백 | 상하좌우 각 8 DIP 이하, 약한 그림자용 |
| 패널 위치 | 기본 캡슐 아래 6 DIP; 오른쪽 정렬 |
| 패널 너비 | 캡슐보다 40 DIP 작음: 기본 480 DIP |
| 패널 모서리 | 14 DIP |
| 패널 패딩 | 좌우12 / 위8 / 아래10 DIP |
| 패널 헤더 | 24 DIP, 뒤 간격4 DIP |
| 요약 행 | 28 DIP, 최대 3개 우선 표시 |
| 일반 미리보기 펼침 높이 | 캡슐+간격+패널 가시 영역 합계 240 DIP 이하 |
| 긴 메모/첨부 편집 펼침 | 가시 높이 320 DIP 이하; 내용은 내부 스크롤 |

### 2.1 한 줄의 폭 계산

내부 Grid 열 예시(520 - 좌우패딩24 = 496 DIP):
`28 / 8 / * / 32 / 4 / 32 / 32 / 64 / 32`

순서: 로고 / 간격 / 입력 / 기록 버튼 / 간격 / 영역 캡처 / 첨부 / 할 일 / 최근 기록.
별도 수평 StackPanel로 입력 너비를 무제한 늘리지 않는다.
기록 버튼이 없는 빈 상태에도 그 32 DIP 슬롯은 유지해 타이핑할 때 전체 레이아웃이 흔들리지 않게 한다.
버튼 자체는 비활성·비포커스·비히트테스트이고 외형은 숨긴다. **부가 패널은 반대로 반드시 공간까지 접는다.**
작업 영역이 부족하면 너비를 먼저 제한하되 글꼴 전체를 Viewbox로 축소하지 않는다.
매우 좁은 작업 영역에서는 영역/첨부 명령을 로고 메뉴로 옮기는 명시적 반응형 모드를 쓰고, 클릭·키보드로 계속 접근 가능하게 한다.
보통 환경에서 임의로 360 DIP 세로창으로 복귀하지 않는다.

### 2.2 배치·복원

- 기존 모니터/위치와 상단 고정 선호는 가능한 한 유지한다.
- 기존 360×500 창의 Height/MinHeight/MinWidth·확장 플래그를 캡슐에 그대로 복원하지 않는다.
- `FloatingLayoutVersion=2` 같은 UI 설정 버전을 도입하고 이전 높이값을 이 창에서 무시한다. DB 기록은 변경하지 않는다.
- 첫 위치가 없으면 작업 영역 우상단에서 24 DIP 정도 안쪽. 작업 표시줄 포함 전체 화면이 아니라 모니터 작업 영역을 사용한다.
- 아래 공간이 모자라면 패널을 캡슐 위로 연다. 캡슐 자체의 화면 좌표는 유지한다.
- 패널이 접히면 실제 창 경계도 축소한다. 보이지 않는 커다란 직사각형으로 다른 앱의 클릭을 막지 않는다.
- 모니터 제거·DPI 변경 후 화면 안으로 보정한다. DIP와 물리 좌표, 음수 모니터 좌표를 구별한다.

## 3. 재질·색·타이포 — 플로팅에만 적용

메인 앱을 이번에 모두 어둡게 바꾸지 않는다. 아래 자원은 Floating 전용 Dictionary/Style로 격리한다.

| 토큰 | 값 |
|---|---|
| CapsuleTintStart | #EB29464B (WPF ARGB) |
| CapsuleTintEnd | #F0374553 (WPF ARGB) |
| PanelBackground | #F01D343C |
| OpaqueFallback | #263D45 |
| BorderHighlight | #4DDFEDF2, 1 DIP |
| TextPrimary | #F2F6F8 |
| TextSecondary | #B9CCD4 |
| IconNormal | #D1E0E7 |
| Accent | #55CFC7 |
| Completed | #75D5B0 |
| Error | #FFB4AB |
| HoverSurface | #14FFFFFF |
| PressedSurface | #24FFFFFF |

- 왼쪽 청록에서 오른쪽 슬레이트로 아주 약하게 변화하는 표면만 허용한다. 무지개·네온·반복 광택은 없다.
- 글자와 아이콘의 Opacity는 1이다. Window 전체 Opacity를 내려 글자까지 흐리게 만들지 않는다.
- 1 DIP의 은은한 밝은 외곽선, 필요하면 약한 그림자 하나. 다중 그림자나 발광 금지.
- 캡슐 안 흰 TextBox, 별도 제목 줄, 큰 파란 사각 버튼, 이모지 아이콘은 없다.
- 기존 라이선스 확인된 로컬 벡터 아이콘을 한 세트로 사용한다. 새 원격 폰트·아이콘 API 호출은 없다.
- 글꼴은 설치된 시스템 글꼴. 한국어 폴백을 지정하고 받침·caret·선택색을 실제 검수한다.
- 키보드 포커스는 보이는 윤곽이나 입력 강조로 남긴다. 미려함을 이유로 포커스 표시를 제거하지 않는다.
- 실제 흰 문서와 어두운 편집기 위에서 모두 읽히는지 검사한다. 고대비/투명 효과 제한 시 불투명 대체 표면과 시스템 가독성을 우선한다.

### 3.1 반투명과 실제 배경 블러를 혼동하지 않는다

기본 납품은 위의 짙은 반투명 유리풍 표면이다. 참고의 유리감은 색·경계·깊이로 먼저 재현한다.
알파 투명만 구현하고 실제 배경을 흐리는 Acrylic을 구현했다고 보고하지 않는다.
현재 스택에서 검증된 시스템 블러 경로가 이미 있고 성능·창 모양을 해치지 않을 때만 선택적으로 유지한다.
이번 작업을 위해 WinUI로 갈아타거나 비공식 합성 API, 화면 반복 캡처/BlurEffect로 데스크톱 블러를 흉내 내지 않는다.
실제 블러를 쓰지 못해도 둥근 캡슐·낮은 높이·짙은 재질을 버리고 기본 흰 창으로 돌아가지 않는다.

## 4. 표시 상태 — 하나의 초안, 하나의 열린 패널

권장 상태는 아래처럼 **표시/입력/패널/저장**으로 나눈다. 전부 합친 거대한 enum을 만들 필요는 없다.

- Visibility: Visible / Hidden
- InputMode: SingleLine / Multiline
- PanelKind: None / Recent / Todo / Draft / Menu
- PersistenceState: Clean / DraftSaved / Saving / Failed
- IsTopmost: 앱의 z-order 선호
- PinnedPreview: None / Todo / Recent — 비활성 시에도 유지할 작은 패널 선호

| 사용자 행동/사건 | 결과 |
|---|---|
| 첫 실행/새 레이아웃으로 전환 | 캡슐만 표시. 기존 데이터로 빈 영역을 미리 늘리지 않음 |
| 입력칸 클릭 | 한 줄 입력 포커스만 획득. 아래 패널 자동 확장 없음 |
| 유효한 한 줄 입력 | 작은 기록 버튼 활성화, 높이52 유지 |
| 시계 클릭 | Recent 패널 토글 |
| 할 일 클릭 | Todo 패널 토글 |
| 두 패널 사이 전환 | 기존 패널을 대체, 높이 누적 없음 |
| 패널의 ‘패널 유지’ 클릭 | 해당 미리보기를 비활성 상태에도 유지 |
| 외부 앱 클릭 | 유지 설정 없는 미리보기/편집 패널 닫힘. 초안은 보존 |
| 이미지 붙여넣기/드롭 | 초안에 첨부하고 Draft 패널로 확인, 자동 기록하지 않음 |
| 저장 성공 | 초안 초기화, 짧은 캡슐 피드백, 이후 None 또는 지정된 유지 패널 |
| 저장 실패 | 텍스트·첨부 유지, 작은 오류/재시도 패널. 자동 재저장 금지 |
| Escape | 메뉴/패널/편집을 먼저 닫음. 초안 삭제 없음 |
| 숨기기 명령 | Visible→Hidden, 초안 보존, 트레이/등록된 단축키로 복귀 |

- 패널 유지 상태에서 임시 Draft/Menu가 필요하면 미리보기를 잠깐 대체하고 종료 후 복귀한다.
- 저장 때문에 메인창을 자동으로 앞으로 띄우거나 날짜를 강제로 바꾸지 않는다.
- hover만으로 패널이 열리고 닫히는 방식은 쓰지 않는다.
- 패널 고정 설정은 외부 클릭에 대한 유지 선호다. Escape·숨기기처럼 사용자가 직접 닫는 조작을 막지 않는다.

## 5. 기록·첨부·한글 입력

### 5.1 가장 흔한 한 줄 기록

`단축키/클릭 → 텍스트 입력 → Enter 또는 인라인 기록 버튼 → 성공 피드백`

- 한 줄 모드 Enter는 기록, Ctrl+Enter도 같은 명령. 빈 입력+첨부0은 명령 실행 불가.
- 이 단축키 처리는 메모 입력 컨트롤에 한정한다. Window 전체 기본 버튼/KeyDown이 메뉴·TODO 입력·체크 조작까지 기록하지 않게 한다.
- Enter는 한국어 IME 조합 확정과 구별한다. 조합을 확정하는 동일 키 이벤트를 저장에 재사용하지 않는다.
- ImeProcessed 키 하나만 확인하거나 고정 수십 ms 대기로 해결했다고 가정하지 않는다. 실제 composition 시작/갱신/완료와 입력 이벤트 순서를 확인한다.
- 일반 Enter 자동 기록이 위험하게 오동작하면 기능을 정상이라 보고하지 않는다. Ctrl+Enter와 버튼 경로는 유지하고 실패 조건을 명시한다.
- 한 줄 입력은 가로 스크롤로 caret이 보이게 한다. 길어진다고 캡슐이 여러 줄로 커지지 않는다.
- 첫 실행의 짧은 도움 또는 입력 도움말에 `Enter 기록 · Shift+Enter 긴 메모`를 제공한다. 안내 때문에 상시 두 번째 줄을 만들지 않는다.
- 기존 초안 debounce·DB 트랜잭션·요청 ID 중복 방지를 재사용한다.
- 성공 피드백은 비어 있는 입력 위치에 `14:32 기록됨`을 약 1.5초 표시한 뒤 placeholder로 돌아간다. 사용자가 다시 입력하면 즉시 사라진다.
- 성공 전에는 초안을 비우지 않는다. 초안 보관 상태는 필요하면 작은 상태 표시/툴팁으로 제공한다.

### 5.2 긴 메모

- Shift+Enter 또는 메뉴의 ‘긴 메모’로 Draft 패널의 여러 줄 편집기를 연다.
- 여러 줄 모드에서는 Enter=줄바꿈, Ctrl+Enter=기록이며 작은 ‘기록’ 버튼도 제공한다.
- 여러 줄 텍스트를 붙여넣으면 내용을 보존한 채 긴 메모 모드로 전환한다. 줄바꿈을 몰래 공백으로 바꾸지 않는다.
- 동시에 편집 가능한 두 TextBox가 같은 초안을 서로 덮어쓰지 않게 한다. 패널 편집 중 캡슐 입력 위치는 읽기 전용 요약으로 전환한다.
- composition 도중 편집기를 이동·교체하지 않는다. 커서/선택/초안 상태를 보존한다.
- 긴 메모 편집기는 보통 96~144 DIP부터 시작하고 전체 펼침 높이 상한 내에서 스크롤한다.
- 닫거나 다른 앱으로 이동해도 초안이 남는다. 캡슐에는 편집 중 상태를 알려 다시 열 수 있게 한다.

### 5.3 첨부

- 사진 아이콘=이미지/파일 첨부 선택. **웹캠 기능이 아니다.**
- Ctrl+V: 입력 포커스가 있을 때 텍스트 또는 지원하는 이미지 처리. 상시 클립보드 감시 없음.
- 이미지/파일 드롭: 캡슐 전체를 명시적 드롭 영역으로 사용. 드래그 진입 때만 외곽 강조와 짧은 안내.
- 이미지 80×56 DIP 정도의 썸네일, 일반 파일은 아이콘+파일명+크기. 처음에는 최대3개, 나머지는 +N으로 접근.
- 전체 파일명·제거 버튼·오류 상태에 접근 가능해야 한다. 이름이 board.png라는 이유만으로 사진이 표시됐다고 간주하지 않는다.
- 첨부가 존재하면 캡슐 첨부 아이콘에 작은 개수 표시. 패널을 닫아도 첨부가 있다는 사실을 확인할 수 있어야 한다.
- 기존 25MB/파일·10개/기록 등 제한과 저장 사본 정책을 보존한다. 실제 코드 설정이 다르면 충돌을 기록한다.
- 캡슐이 파일을 받았다는 이유만으로 Entry를 자동 생성하지 않는다. 사용자가 기록을 확정한다.

## 6. 캡슐 아래의 작은 기록/TODO 패널

### 6.1 최근 기록

- 시계 버튼으로 열고 같은 버튼으로 닫는다.
- 헤더 `최근 기록`, 오른쪽에 `패널 유지` 아이콘과 `하루 전체` 액션.
- 오늘 기록 중 최신3개를 선택하고 그 세 개를 시각 오름차순으로 표시한다. 오늘의 전체 로그라고 부르지 않는다.
- 각 행: HH:mm / 유형 아이콘 / 내용1줄 / 선택적 작은 썸네일. 제목은 말줄임하고 상세로 원문 접근.
- 완료 행은 체크+‘완료’를 표시. 과거 완료 기록과 현재 TODO 상태를 섞지 않는다.
- 행 클릭은 기존 메인창의 같은 날짜·같은 Entry 상세를 연다. ‘하루 전체’는 기존 타임라인을 연다.
- 오늘 기록0이면 한 줄 빈 상태만. 예시 기록을 운영 데이터로 표시하지 않는다.
- 완료/저장 알림이 들어와도 읽는 중인 앱을 강제 활성화하지 않는다.

### 6.2 할 일

- 할 일 버튼은 업무를 완료하는 버튼이 아니라 Todo 패널을 여는 버튼이다.
- 캡슐의 작은 숫자 배지는 미완료 수. 0이면 생략하거나 0의 억제된 상태로 표시하고 오류로 표현하지 않는다.
- 헤더 `남은 할 일 N`, 패널 유지 아이콘, 전체 목록 접근.
- 미완료 최대3개 우선 표시. 더 있으면 ‘전체 N개 보기’; 이 작은 패널을 긴 관리창으로 만들지 않는다.
- 한 행: 왼쪽 체크 컨트롤+제목1줄. 충분한 클릭 영역과 키보드 조작을 유지한다.
- 하단 `+ 할 일 추가` 클릭 시 1줄 입력과 작은 추가 조작을 펼친다. 항상 긴 빈 입력란을 예약하지 않는다.
- 입력 중 Enter/추가 버튼으로 생성. IME 조합 확정은 추가로 처리하지 않는다.
- 체크 → DB 커밋 성공 → 활성 행 제거 → 타임라인 완료 이벤트. 기존 원자성/중복 방지 적용.
- 피드백 `완료 기록이 남았습니다 · 실행 취소`는 작은 패널 내부에서 제공한다. 새 거대한 토스트 창을 만들지 않는다.
- TODO0이면 ‘남은 할 일이 없어요’와 추가 액션만 있는 짧은 패널이다.
- ‘패널 유지’를 켜면 다른 앱 작업 중에도 작은 TODO 패널이 계속 보인다. 앱 자체의 Topmost 설정과 독립적으로 저장한다.

## 7. 사용자 실행 1회 영역 캡처 — 이번에만 추가된 범위

영역 아이콘은 실제로 동작해야 한다. 캡처 아이콘만 그려두고 파일 선택창으로 대체하거나 성공 메시지만 띄우지 않는다.

1. 사용자가 영역 아이콘을 누른다.
2. 초안을 보존하고 캡슐/패널을 잠깐 숨긴다.
3. 선택 오버레이로 영역을 드래그한다. Escape는 취소다.
4. 선택 완료 후 오버레이를 숨기고 선택 직사각형만 캡처한다. 자신의 캡슐/선택 마스크가 찍히지 않게 한다.
5. 결과를 현재 초안 첨부로 추가하고 캡슐+Draft 미리보기를 복원한다.
6. 사용자가 Enter/기록 버튼으로 확정해야 타임라인에 저장한다.

- `IRegionCaptureService`처럼 플랫폼 경계를 분리하고 기존 첨부 파이프라인으로 전달한다.
- 현재 스택에서 지원되는 Windows 캡처 경로를 사용한다. 기술 노트의 API는 후보이며 현재 타깃에서 직접 빌드·실행한다.
- 화면 영역은 물리 픽셀 좌표다. DPI·음수 좌표·모니터 경계에서 위치를 검수한다.
- 캡처 실패/권한 차단/잠금 세션은 안내 후 입력 복원. 보안 기능을 비활성화하지 않는다.
- 0 크기 선택·취소 시 빈 이미지·기록 생성 없음. 전체 화면 임시 이미지를 디스크에 남기지 않는다.
- 자동 녹화, 주기적 화면 수집, 전역 클립보드 감시, OCR, 웹캠, 마이크, 원격 전송은 없다.
- 사내 정책이 화면 캡처를 금지하면 기능을 비활성화하고 해당 사유를 표시한다. 붙여넣기·첨부 등 허용된 경로만 유지한다.
- 캡처가 차단된 경우에도 캡슐 UI 작업은 계속하며 최종 결과에 부분 미검증/제한을 명시한다.

## 8. WPF 구현 지시 — 경량 캡슐에 필요한 창 구조만 변경

### 8.1 창 외곽

현재 프로젝트가 WPF일 때의 기본 구현 방향:

```text
WindowStyle = None
AllowsTransparency = True
Background = Transparent
Opacity = 1
ResizeMode = NoResize
ShowInTaskbar = False
Topmost = 기존/신규 상단 고정 설정
ShowActivated = False (자동 표시 시, Show 전에 설정)
```

이 설정 목록은 완성 코드가 아니다. 기존 트레이/명령/수명주기에 연결해야 한다.
WPF 공식 문서상 AllowsTransparency=True는 WindowStyle=None과 함께 사용한다.
반경26은 앱이 캡슐 표면에 직접 적용한다. per-pixel 투명 창에 OS 모서리 둥글림 API까지 겹쳐 해결하려 하지 않는다.
WindowChrome이나 OS 타이틀바 유지가 이 캡슐 모양을 대체하지 않는다.

권장 트리:

```text
FloatingCapsuleWindow (transparent host, 내용만큼 실제 bounds)
  Root Grid (transparent shadow gutter)
    CapsuleBackground (rounded, optional single background-only shadow)
    CapsuleContent Grid (실제 TextBox/Button/ToggleButton)
    AuxiliaryPanelHost (None이면 Collapsed; Recent/Todo/Draft/Menu 중 하나)
```

### 8.2 마이그레이션과 공통 컴포넌트

- 기존 `QuickCaptureComposer`의 세로 UI를 그대로 캡슐 내부에 넣지 않는다.
- 텍스트·첨부·저장 명령/서비스만 재사용하고, 캡슐 전용 View를 만든다.
- 메인 화면에서도 사용하는 공통 버튼 Style을 전역으로 바꿔 모든 화면을 어둡게 만들지 않는다.
- 이름은 기존 구조에 맞춰 정하되 예: `FloatingCapsuleWindow`, `CapsuleInputBar`, `FloatingAuxiliaryPanel`, `CompactLogRow`, `CompactTodoRow`.
- 상태/배치는 작은 ViewModel과 placement 서비스로 분리한다. DB 규칙을 code-behind로 이동하지 않는다.
- 장식 Border를 클릭 버튼처럼만 쓰지 않는다. 실제 Button/ToggleButton/TextBox와 접근성 이름을 보존한다.
- 새로운 UI 라이브러리·웹 런타임·서버를 추가하지 않는다.

### 8.3 창 조작·포커스

- 로고 클릭은 앱 메뉴. 로고/명시된 빈 표면 드래그는 이동. 시스템 드래그 임계치를 넘었을 때만 이동하며 클릭 메뉴와 구분한다.
- 입력 텍스트 선택, 아이콘 클릭, 패널 체크를 창 드래그로 처리하지 않는다.
- 로고 메뉴: 하루의 흐름 / 긴 메모 / 항상 위 ON·OFF / 숨기기 / 기존 설정 / 앱 종료.
- 기존 트레이 복귀·종료 경로를 보존한다. 창 제목줄 X가 사라졌다고 종료 기능까지 없애지 않는다.
- 단축키는 이미 등록된 설정을 유지한다. 참고 이미지의 Ctrl+Shift+L은 실제 등록 성공 때만 표시한다.
- ShowActivated=False는 자동 표시 때의 초기 활성화를 제어하는 수단이다. 클릭/호출 뒤 정상 입력 활성화는 허용한다.
- 전역 WS_EX_NOACTIVATE로 입력창을 영구 비활성화해 IME를 깨뜨리는 구현은 피한다.
- 반복 Activate()/Topmost 토글 루프로 항상 위를 흉내 내지 않는다.
- 메뉴/파일선택/IME 후보창이 열리는 것을 외부 클릭으로 오인하여 입력 패널을 닫지 않는다. 앱 소유 창과 실제 외부 활성화를 구별한다.
- 바깥 투명 영역의 native 히트테스트를 실제 검수한다. WPF IsHitTestVisible=False만으로 다른 프로그램 클릭이 통과한다고 단정하지 않는다.
- Tab 순서·버튼 툴팁·접근성 이름·Space/Enter·보이는 포커스를 유지한다.

## 9. ‘초경량’의 측정 범위

작은 화면이라는 의미와 적은 자원 사용이라는 의미를 구별해 보고한다.
이번 외형 합격 기준은 기본 높이52 DIP다. 자원 사용은 아래 **초기 목표**를 측정해 보고하며 측정 없이 달성했다고 쓰지 않는다.

- 유휴60초 CPU 평균: 전체 논리 CPU 용량 기준 1% 이하 목표.
- 이미 실행 중인 캡슐 호출: p95 200ms 이하 목표, 실제 측정 횟수·환경 보고.
- 메인 미개방 캡슐 실행 시 Working Set 120MiB 이하를 초기 목표로 측정. 기존 프로세스 구조의 제약과 전후 차이도 보고.
- WorkingSet64와 PrivateMemorySize64를 함께 보고한다. 열린 메인창 메모리까지 ‘플로팅만’으로 부르지 않는다.
- CPU 계산 예: processCpuDelta / (wallTimeDelta × logicalProcessorCount) × 100.
- 고빈도 DB 폴링, 초 단위 실시간 시계 갱신, 상시 애니메이션, 화면 반복 캡처 없음.
- 최근 기록3개/할 일3개에 필요한 조회만. 큰 이미지 원본을 UI에 다수 유지하지 않는다.
- 숨겨진 동안 불필요한 타이머/미리보기 작업 중지. 캡처·이미지 스트림·GDI 자원은 사용 후 정리한다.
- 기존 DB·파일 비동기/직렬화 경계를 유지하고 UI 스레드에 이미지 해시·복사·압축을 올리지 않는다.

## 10. 무인 실행 순서 — 이번 범위 전체 완주

### C0: 실제 원인·기준선
기존 창/스타일/Height·MinHeight·복원 코드/기능 테스트를 조사한다. 사용자 변경 보존. 현재 플로팅 실제 캡처 확보.
기존 명세의 충돌 구절을 이 문서로 대체하고 변경 매핑을 남긴다.

### C1: 캡슐 외곽+입력
실제 플로팅 실행 경로를 캡슐로 교체한다. 실제 OS 창 기준52 DIP 외형을 먼저 확인한다.
제목표시줄/세로 편집기/빈 TODO가 남으면 먼저 수정한다. 표본 페이지 제출만으로 끝내지 않는다.

### C2: 작은 패널+저장 연결
최근 기록, 할 일, 첨부·긴 메모, 완료/실행 취소, 오류를 기존 서비스에 연결한다.
운영 데이터에 합성 자료를 넣지 않는다. 초안·선택·상태 보존 검수.

### C3: 1회 영역 캡처+Windows 동작
수동 영역 캡처, 창 이동·상단 고정·트레이·IME·DPI·다중 모니터를 가능한 환경에서 검사한다.
회사의 승인 범위를 벗어나는 캡처는 우회하지 않는다.

### C4: 실행 캡처·회귀·패키징
실제 OS 화면 캡처를 기준으로 최대3회의 비교·수정을 수행한다. 기능/시각 테스트의 실패를 구분해 수정한다.
기준 미달을 반복 횟수만 채웠다고 합격 처리하지 않는다. U2/U3 메인 전체 재작업으로 넘어가지 않는다.

매 단계 사용자 승인 대기는 없다. 실행할 수 없는 검수는 NOT RUN/BLOCKED다.
외부 승인/환경 문제로 일부가 막혀도 안전하고 독립적인 작업은 계속한다.
결과물은 수정 빌드이며, 남은 기능 회귀가 있으면 ‘사용 가능한 완성품’이라고 표시하지 않는다.

## 11. 최종 증거·완료 조건

`02_ACCEPTANCE.md`를 실제 실행으로 채운다. 최소 결과물:

1. 전체 소스와 기존 배포 경로의 실행 빌드.
2. OS 창 캡처: 기본 캡슐 / 한 줄 입력 / 최근 기록3개 / TODO3개 / 첨부 이미지 / 오류.
3. 흰 문서 위와 어두운 편집기 위의 캡슐 캡처. 합성 자료만 사용.
4. 캡슐 호출→한글 기록→첨부→TODO 완료→타임라인 확인→접힘의 실제 짧은 영상 또는 단계별 OS 캡처.
5. 기존 테스트 결과, 추가 테스트, 측정한 가시 표면 크기/실제 창 bounds/Windows 배율.
6. 성능 전후 수치와 미검증/미해결 목록.

RenderTargetBitmap은 보조 컴포넌트 렌더 검사용이다. 창 외곽·상단 고정·배경 합성·OS 포커스를 그것 하나로 증명하지 않는다.
OS 캡처를 자르고 확대해서 큰 창을 작은 캡슐처럼 보이게 하지 않는다. 원본과 읽기용 크롭을 구별한다.
정적 목업, 생성 이미지, 운영 데이터를 꾸민 화면은 실행 증거가 아니다.

최종 보고 첫 문장에 판정을 쓴다:
`플로팅 캡슐: 구현/부분 구현 — 외형 XX/YY PASS — 동작 XX/YY PASS — NOT RUN 항목 ...`
‘U0 승인 대기, 다음은 U1’이라는 결과로 종료하지 않는다.
