# FlowNote 0.5.1 — 감사 후속 수정

기준 소스: v0.5.0 (`0758765176ef1894a296edeffc79478cb37b9fc6`).
원래 mango PC는 오프라인이므로, 온라인 DESKTOP-IEJM3L1의 별도 clone에서 수정했다.
기존 사용자 DB와 오프라인 PC의 미커밋 파일은 열거나 수정하지 않았다.

## 변경

- 혼합 문장에서 같은 구문을 재귀 분석하던 경로를 제거했다. 분리할 단서가 부족하면 원문을 보존하고 판단을 보류한다.
- A 수행과 처음 등장한 B 요청이 한 기록에 있어도 B를 누락하지 않는다.
- 요청/계획 마커는 수행 이력이나 A→B→A 복귀 판단에 사용하지 않는다.
- 일부 완료 부정 표현을 CompletionMention으로 분류하지 않도록 반례를 추가했다.
- 늦은 분석 실패/취소는 현재 running 상태와 attempt가 일치할 때만 작업 상태를 변경한다.
- 모델·규칙·프롬프트 버전이 바뀐 뒤 도착한 결과는 적용하지 않는다.
- worker 시작을 UI Dispatcher 밖으로 옮겼다. 모든 UI/DB 경로가 비동기로 전환됐다는 뜻은 아니다.
- 평상시 시작은 캡슐만 표시한다. 설정에는 어셈블리 버전/빌드 ID를 표시한다.
- 파노라마/할 일/설정에서 검색 결과로 이동하고 검색 결과 없음도 표시한다.
- 원문 확장에 제목 중복 제거용 미리보기를 사용하지 않는다. 짧은 원문도 표시한다.
- 좁은 창 상세는 기존 패널 하나로 표시하고 스크롤할 수 있다.
- smoke 및 core 제거 스크립트의 프로세스 이름 전체 강제 종료를 제거했다.

## 검증 근거

- 원격 main 기준 테스트: Core 85 / Infrastructure 67 통과.
- 추가 반례에서 Core 5건, 늦은 분석 오류 1건의 실패를 먼저 확인했다.
- 수정 뒤 Core 96 / Infrastructure 70 = 166건 통과. 실패 0.
- 기존 복귀 시험의 B가 잘못 `IsWorkSegment=false`로 돼 있어 true로 정정했다.
  별도 회귀 시험으로 요청(false)이 복귀를 만들지 않는 반대 조건을 추가했다. assertion을 삭제하지 않았다.
- 재귀 위험은 이전 코드를 실제로 stack overflow 시키지 않고 정적 확인했다. 수정 코드에는 무구두점 반례를 추가했다.
- 실제 WPF smoke와 재실행 검수, 검색/버전 표시 검수를 수행했다.
- 별도 normal profile에서 Windows UI Automation으로 캡슐 단독 시작(536×68 OS 창), 입력·기록 버튼 실행·최근 기록 표시를 확인했다.
- UI Automation에서 제품의 `종료` 버튼으로 해당 테스트 프로세스가 정상 종료됐다.
- 최종 태그의 publish 결과를 다시 압축 해제하여 smoke하고, 자산 해시와 build ID를 배포 verification.json에 기록한다.

## 범위와 남은 제한

실제 사람의 한국어 IME 조합, 150% 이상 배율, 코드 서명, 새로운 실제 LLM 의미 평가는 NOT RUN이다.
규칙 기반 성공을 과거 MODEL_REAL FAIL의 해결이라고 보고하지 않는다.
원문·첨부 저장과 기본 파노라마는 모델 없이 동작한다. 모델과 llama-server는 이번 ZIP에 없다.
규칙의 모든 자연어 표현 일반화를 보장하지 않는다. 복잡한 단일 문장은 보류될 수 있다.
기존 전체 DB 조회/worker 종료 시간제한의 잔여 성능·수명 관리 문제는 완전히 해결했다고 주장하지 않는다.

빌드 PC의 PowerShell 실행 정책을 변경하지 않았다. 직접 dotnet 명령으로 빌드/검수했다.
설치 도구 준비 명령은 도구 계층의 `spawn EPERM`으로 실행되지 않아 설치 EXE를 생성하지 않았다. 배포물은 self-contained 포터블 ZIP이다.
