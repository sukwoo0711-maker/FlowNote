# FlowNote Desktop 외주 패키지 — 먼저 읽기

이 패키지는 **외주를 위한 프롬프트·기능 명세·검수 기준**이다. 앱 소스코드나 이미 구현된 프로그램이 아니다.

핵심: **빠른 기록 → TODO 완료 이력 → 하루 타임라인/파노라마 → 근거 확인 → 선택 내보내기**.

## 미확정 결정

| 결정 | 이 패키지의 잠정안 | 답변에 따른 영향 |
|---|---|---|
| 최초 판매 대상 OS | Windows 11 x64 우선 | macOS 동시 지원이면 WPF 잠정안을 바꿔야 한다. |
| Worker의 기존 스택·저장소 | 지정 없음, 새 WPF 프로젝트 가정 | Flutter 등 기존 코드가 있으면 무단 재작성하지 않는다. |
| 시간 기능 | 기록 시각 + 사용자가 지정하는 발생 시각 | 시작/일시정지/종료 타이머가 필요하면 별도 설계한다. |
| 회사의 저장 암호화 요구 | 앱 자체 암호화 미포함 | 암호화가 필수면 현재 저장·백업 설계로 배포하지 않는다. |

이 네 가지를 발주자가 확인한다. 이미 알려진 회사 Jira REST API 제한을 재확인 명목으로 우회하거나 해제된 것으로 가정하지 않는다.

## 발주 범위의 경계

참고 이미지의 모든 기능을 자동으로 발주한 것이 아니다. 스마트폰 UI·다중 플랫폼·AI·음성·동기화 로고·작업시간 통계는 제외/조건부 항목이다.

Windows 우선안은 기존 데스크톱 사용 맥락을 바탕으로 제안한 것이며, 사용자가 첫 제품 플랫폼을 확정했다는 뜻은 아니다.

제품명 FlowNote는 시안용 가칭이며 상표·도메인 사용 가능성을 검증한 이름이 아니다.

## 0. 당신의 역할과 이번 작업의 결과물

당신은 이 프로젝트의 Windows 데스크톱 개발 담당자다. 기획 아이디어, 웹사이트, 이미지 목업만 만드는 사람이 아니다. 실제로 실행되고, 데이터를 저장하며, 재실행해도 복구되고, 사용자가 검수할 수 있는 프로그램을 구현한다.

제품의 중심은 일반 메모장이나 TODO 보드가 아니다.

> 일하는 도중 남긴 메모·이미지·자료와 완료한 일을 하나의 시간 흐름으로 연결하여, 하루가 끝났을 때 내가 무엇을 했고 어떤 근거를 남겼는지 되돌아보는 개인 업무 타임라인이다.

화면의 목적과 우선순위는 다음과 같다.

1. 핵심 가치: 하루 타임라인을 통해 업무 흐름과 근거를 확인한다.
2. 입력 경로: 항상 위에 표시되는 작은 창에 메모·이미지·파일을 빠르게 남긴다.
3. 자동 연결: 할 일을 완료하면 활성 목록에서는 사라지고 타임라인에는 완료 기록으로 남는다.
4. 활용 결과: 필요한 기록과 근거만 선택하여 업무 보고에 재사용한다.

기능을 많이 만드는 것보다 이 네 단계가 실제 데이터로 끝까지 연결되는 것을 우선한다.

### 0.1 현재 확인된 사용자 요구

- 회사 업무 중 사용하는 데스크톱 앱이다.
- 메모와 TODO를 항상 위에 두고 싶다.
- 텍스트·사진 등 멀티모달 기록에 자동 시각이 붙어야 한다.
- TODO 완료는 기록의 삭제가 아니라 업무 이력으로의 보관이다.
- 하루를 시간순·파노라마로 돌아보는 기능이 제품의 핵심이다.
- Jira 같은 업무 도구와 기록·근거를 연결하는 확장 가능성이 필요하다.
- 이전 대화에서 회사 Jira/Confluence REST API 사용 제한이 언급되었다. 이 제한을 우회하지 않는다.

### 0.2 사용자 답변 전 잠정 기준

| 항목 | 잠정 결정 | 취급 방법 |
|---|---|---|
| 첫 플랫폼 | Windows 11 x64 | macOS도 첫 출시 대상이면 스택부터 재검토한다. |
| 기술 스택 | C# / .NET 10 LTS / WPF | 기존 저장소나 사용자 지정 스택이 확인되면 임의 교체하지 않는다. |
| 첫 납품 단계 | 실제 사용하는 비공개 베타 | 결제·라이선스·공개 배포 준비 완료를 뜻하지 않는다. |
| 기록 방식 | 수동 입력·붙여넣기·파일 선택 | 화면·클립보드 자동 수집은 하지 않는다. |
| 시간 | 자동 기록 시각 + 선택적 실제 발생 시각 | 타이머·근무시간 추정은 V1에서 제외한다. |
| 저장 | 로컬 SQLite + 로컬 첨부 폴더 | 앱 자체 파일 암호화는 미포함이다. 정책상 필수면 구현 전 재설계한다. |
| 외부 도구 | 이슈 번호/URL 수동 연결 + 선택 내보내기 | Jira API, 자동 댓글·첨부·상태 변경은 미포함이다. |
| 테마 | 밝은 테마 우선 | 어두운 테마는 후속 범위다. |

잠정 기준으로 기획과 독립적인 핵심 로직은 준비할 수 있다. 그러나 Windows 전용 납품, 암호화 없는 사내 배포 등 되돌리기 큰 결정은 사용자 확인 없이 확정하거나 배포하지 않는다.

### 0.3 문서 우선순위

사용자가 이후 명시적으로 확정한 변경 > 이 구현 명세 > 검수 시나리오 > 작업 분할표 > 참고 이미지 순서로 적용한다.

충돌을 발견하면 `docs/DECISIONS.md`에 충돌과 해결을 기록한다. 이미 답변이 있는 내용을 다시 묻지 않는다. 권한·보안·데이터 손실·대상 플랫폼을 바꾸는 결정은 임의 가정으로 진행하지 않는다. 단순 여백이나 내부 함수명처럼 되돌리기 쉬운 결정은 여기의 기본값으로 진행한다.

## 1. 참고 이미지 해석: 포스터를 앱으로 착각하지 말 것

첨부 경로:

### 살릴 것

밝은 바탕, 흰색 표면, 절제된 파란 강조색, 선명한 시간 숫자, 노드와 연결선, 읽기 쉬운 카드, 첨부 이미지 썸네일, 완료 상태의 시각적 구별을 살린다.

### 그대로 옮기지 말 것

- 스마트폰 프레임, 모바일 하단 탭, 중앙의 과장된 원형 추가 버튼.
- 홍보용 산·책상 사진, 거대한 캐치프레이즈, 다운로드 배너.
- 미구현 Jira/Notion/Slack/모바일 동기화 로고와 지원 표기.
- 실제 측정하지 않은 집중시간·근무시간·성과 지표.
- 음성 녹음·AI 요약·영상 분석 등 사용자가 확정하지 않은 기능.
- 의미 없는 그라데이션 카드, 모든 요소에 붙이는 그림자, 이모지 아이콘.

데스크톱의 넓은 폭을 사용하여 좌측 탐색, 중앙 하루 흐름, 우측 근거 상세를 구성한다. 앱을 좁은 휴대전화 화면처럼 가운데 배치하지 않는다.

첨부 PNG 자체를 앱 배경으로 깔고 투명 버튼을 얹는 구현은 금지한다. 화면 구성 요소는 실제 XAML 컨트롤이어야 한다.

## 3. 실행 환경과 구현 구조

Windows 전용 잠정안이 확정되면 다음으로 구현한다.

- .NET 10 LTS의 개발 시점 지원되는 안정 패치. Preview 사용 금지.
- `net10.0-windows`, C#, WPF, MVVM.
- `Microsoft.Data.Sqlite`: 직접 SQL과 명시적 트랜잭션 사용.
- `CommunityToolkit.Mvvm`: ViewModel과 명령 바인딩에 한정하여 사용 가능.
- 테스트: xUnit. 테스트 프로젝트의 패키지는 런타임에서 분리한다.
- 런타임 아이콘은 로컬 벡터 리소스 한 세트. 출처·라이선스를 기록한다. 이모지 대체 금지.
- 시스템 트레이는 Windows Forms `NotifyIcon`을 사용하는 작은 서비스로 분리할 수 있다. WPF/Forms 이름 충돌은 명시적 네임스페이스로 해결한다.
- 서버, 브라우저 런타임, WebView, Electron, Rust를 추가하지 않는다. 이것이 다른 스택보다 항상 우수하다는 뜻이 아니라 이번 Windows 잠정안의 범위를 고정하는 것이다.

권장 구조:

```text
FlowNote.sln
src/
  FlowNote.Core/
    Models/
    Rules/
    Abstractions/
  FlowNote.Infrastructure/
    Persistence/
    Attachments/
    Backup/
    Export/
  FlowNote.Desktop/
    App.xaml
    Views/
    ViewModels/
    Controls/
    Themes/
    Platform/
    Assets/
tests/
  FlowNote.Core.Tests/
  FlowNote.Infrastructure.Tests/
docs/
  SPEC.md
  DECISIONS.md
  PROGRESS.md
  TEST_RESULTS.md
  KNOWN_ISSUES.md
  screenshots/
scripts/
  build.ps1
  test.ps1
  publish.ps1
```

규칙:

- View/XAML: 표시, 배치, 시각 상태만 담당한다.
- ViewModel: 화면 상태와 사용자 명령을 연결한다.
- Core: 완료·재열기·시각·집계 같은 규칙을 담당한다. WPF나 SQLite를 참조하지 않는다.
- Infrastructure: DB·파일·백업·내보내기를 담당한다.
- Windows 전용 서비스: 창 위치, 상단 고정, 단축키, 트레이를 담당한다.
- 창 이동·IME·포커스 같은 UI 전용 처리는 code-behind에 둘 수 있다. DB 쿼리와 업무 규칙을 넣지는 않는다.
- `Task`라는 도메인 클래스 대신 `WorkItem`을 사용하여 비동기 `Task`와 혼동하지 않는다.
- 단순한 모델에 CQRS, 마이크로서비스, 범용 플러그인 계층, 과도한 추상 팩토리를 도입하지 않는다.
- 전체가 하나의 거대한 `MainWindow.xaml.cs`가 되지 않도록 한다.
- SDK 버전과 실제 패키지 버전을 고정하고 잠금 파일을 제출한다. 런타임 버전과 SDK 버전 숫자를 혼동하지 않는다.

공식 근거는 `05_TECHNICAL_REFERENCES.md`에 있다. 특히 WPF는 Windows 전용이고, SQLite의 Async 이름만으로 UI 스레드 비차단이 보장되지 않는 점을 반영한다.

## 6. 화면별 상세 명세

### O01. 첫 실행 안내

목적: 장황한 가입 없이 저장 방식과 기본 조작을 이해시키기.

- 제목: `일하는 순간을 남기고, 하루의 흐름을 확인하세요.`
- 안내: `메모와 첨부파일은 이 PC의 로컬 폴더에 저장됩니다.`
- 현재 잠정안에서는 파일 자체가 암호화되지 않음을 명확하게 알린다.
- 저장 위치를 보여주되 V1에서 임의 네트워크 드라이브·클라우드 동기화 폴더로 바꾸는 기능은 넣지 않는다.
- `Windows 로그인 시 시작`은 기본 OFF.
- `플로팅 창 항상 위에 표시`는 기본 ON.
- 버튼: `기록 시작` / 보조: `예시로 둘러보기`.
- 예시 모드는 별도 DB·첨부 폴더에서만 실행한다. 실제 사용자 DB에 데모를 섞지 않는다.
- 자동 실행·캡처·외부 전송 권한을 한 번에 묶어서 허용시키지 않는다.

### F01. 플로팅 기록·TODO 창

**SUPERSEDED BY docs/FLOATING_CAPSULE_V2.md** — 360×500 세로 메모장, 기본 제목 표시줄, 오늘/고정/접기/숨기기 텍스트 줄, 상시 TODO, Enter 줄바꿈은 폐기한다. 플로팅 외형은 제목 표시줄 없는 520×52 DIP 캡슐만 따른다.

목적: 다른 프로그램을 떠나지 않고 한 줄로 기록하고, 필요할 때만 작은 패널에서 최근 기록·할 일을 본다.

기본 가시 표면: 520×52 DIP, 끝 반경 26 DIP. 패널이 없으면 실제 창 경계도 축소한다(여백 각 8 DIP 이하). 구형 높이 설정은 복원하지 않는다.

상단(캡슐): 로고 메뉴, 한 줄 입력, 인라인 기록/영역캡처/첨부/할 일/최근. `오늘 / 고정됨 / 접기 / 숨기기` 텍스트 버튼 줄을 두지 않는다.

입력:

- placeholder: `지금 떠오른 것을 기록하세요…`
- 한 줄 모드 Enter 또는 인라인 기록, Ctrl+Enter도 동일. 빈 입력+첨부 0은 실행 불가.
- 한국어 IME 조합을 확정하는 Enter는 기록하지 않는다.
- 긴 메모는 Shift+Enter 또는 메뉴로 작은 편집 패널. 그때만 Enter 줄바꿈 / Ctrl+Enter 기록.
- 텍스트 없이 사진이나 파일만 저장하는 것도 허용한다.
- 본문은 최대 20,000자다. 초과 시 이유를 안내하고 몰래 잘라 저장하지 않는다.
- Escape는 열린 패널/메뉴를 닫는 데 사용하되 초안 삭제 단축키로 사용하지 않는다.
- 필수 제목·프로젝트·태그를 요구하지 않는다.
- 첨부 미리보기(사진은 실제 썸네일), 파일명, 크기, 제거 버튼을 패널에서 표시한다.
- 성공 피드백은 입력 위치에 `HH:mm 기록됨`. 실패 시 초안·첨부를 보존한다.

할 일·최근 기록:

- 기본 상태에 상시 TODO 목록과 빈 추가 입력란을 두지 않는다.
- 할 일 아이콘으로 작은 패널을 연다. 미완료 최대 3개, 체크 완료는 DB 커밋 후 목록에서 제거.
- `완료 기록이 남았습니다 · 실행 취소`는 패널 안에서 제공한다. 실행 취소는 다시 열기 이벤트를 남긴다.
- 패널 유지와 창 Topmost는 별도 설정이다.

창 동작:

- Topmost 기본 ON. 사용자가 OFF로 바꾸면 일반 창처럼 동작하고 재실행해도 유지한다. 패널 유지와는 별도다.
- 자동 저장, 목록 갱신, 완료 피드백 때문에 타 앱 포커스를 빼앗지 않는다. 저장 때문에 메인 날짜를 강제로 바꾸지 않는다.
- 사용자가 창을 클릭하거나 기록 단축키를 누른 경우에만 입력 포커스를 준다. `ShowActivated=False`는 자동 표시에만 쓴다.
- 기본 상태는 한 줄 캡슐이다. TODO가 없어도 높이를 늘리지 않는다.
- 제목 표시줄 X가 없으므로 숨기기는 로고 메뉴·트레이다. 실제 종료는 트레이의 `앱 종료`다.
- 드래그는 로고/빈 표면에서 시스템 드래그 임계치 이후만. 본문 선택·아이콘 클릭을 창 이동으로 처리하지 않는다.
- 단축키 기본 제안: 기록 `Ctrl+Alt+Space`, 오늘 보기 `Ctrl+Alt+T`, 전체 창 숨기기 `Ctrl+Alt+H`.
- 위 조합이 항상 비어 있다고 가정하지 않는다. 등록 실패 시 해당 기능을 트레이로 제공하고 설정에서 변경할 수 있게 한다.
- 단축키 처리에 전역 키로깅 훅을 사용하지 않는다.
- 숨기기 기능은 화면 녹화·화면 공유에서의 완전한 비노출 보장이 아니다. `보안 모드`라고 이름 붙이지 않는다.

### T01. 하루 시간순 보기 — 기본 메인 화면

이 앱의 기본 메인 화면은 통계 대시보드가 아니라 하루 타임라인이다.

상단 순서:

1. `오늘의 흐름` 제목, 이전 날짜, 선택 날짜, 다음 날짜, `오늘` 버튼.
2. `기록 N개 · 완료 업무 M개 · 첨부 K개`의 작은 요약. 숫자는 8장의 정의대로 계산한다.
3. `[시간순] [파노라마] [업무별]` 보기 전환.
4. 프로젝트/업무/유형 필터, `필터 초기화`, `하루 정리` 버튼.

중앙 타임라인:

- 오래된 기록에서 최신 기록 순으로 위→아래 정렬.
- 왼쪽 64~72 DIP는 시각, 다음은 노드와 연결선, 나머지는 카드.
- 메모·이미지·파일 기록은 같은 카드 구조를 사용하고 내용에 따라 내부만 바꾼다.
- TODO 생성/완료/재열기/취소는 간결한 이벤트 행으로 표시한다.
- 완료는 체크 아이콘과 `완료`, 재열기는 `다시 열림`, 취소는 `취소됨`을 텍스트로 표시한다.
- 카드에서 제목/본문 미리보기, 첨부 최대 3개, 업무/이슈 연결을 확인할 수 있어야 한다.
- 첨부 4개 이상은 `+N`으로 상세 연결한다.
- 카드 클릭 시 D01 상세를 연다. 더보기 메뉴와 체크박스 클릭은 카드 선택과 충돌하지 않게 한다.
- 날짜 내 기록 간격이 길면 선택적으로 `이 구간에는 기록이 없습니다`를 표시한다. `휴식`, `자리 비움`, `미근무`로 해석하지 않는다.
- 같은 분에 여러 기록이 있어도 병합해서 내용을 없애지 않는다.
- 기록이 0개면 `아직 기록이 없습니다`와 `첫 기록 남기기`를 표시한다.

조회 중 실시간 추가:

- 사용자가 목록 끝을 보고 있을 때만 새 기록으로 따라간다.
- 과거 기록을 보고 있으면 스크롤 위치를 유지하고 `새 기록 N개` 버튼을 보여준다.
- 다른 날짜에 새 기록이 생겨도 선택한 날짜를 강제로 오늘로 바꾸지 않는다.
- 보기 전환 후에도 선택한 날짜·필터·기록을 유지한다.

### T02. 하루 파노라마 보기 — 핵심 차별화 화면

목적: 하루의 기록을 가로로 펼쳐 큰 흐름을 먼저 보고, 필요한 사건으로 들어가기.

파노라마를 장식용 Gantt 차트로 구현하지 않는다. V1에 작업시간 측정이 없으므로 기록을 소요시간 막대로 그리지 않는다.

#### 위쪽: 하루 전체 미니맵

- 높이 약 72~88 DIP. 00:00~24:00 전체가 현재 중앙 영역 폭 안에 들어오게 한다.
- 시간 눈금은 좁은 화면에서 00/06/12/18/24 정도로 간소화한다.
- 기록은 점/작은 클러스터로 표현한다. 점 크기나 색을 생산성으로 해석하지 않는다.
- 밀집한 구간은 15분 단위 클러스터와 개수로 표시할 수 있다.
- 노드가 하나면 해당 기록을 선택하고, 여러 개면 해당 구간 목록을 연다.
- 클릭한 시각/구간으로 아래 확대 파노라마를 이동한다.
- 선택 범위 표시는 '현재 보는 범위'이며 업무시간이 아니다.
- 날짜에 기록이 없으면 빈 축과 빈 상태를 보여준다.

#### 아래쪽: 시간 버킷형 확대 파노라마

- 가로 스크롤되는 24개의 시간 열. 각 열은 약 180 DIP를 기준으로 동일한 폭이다.
- 열 제목은 `09시`, `10시`처럼 실제 시각이다.
- 각 열 안에는 해당 시각대 기록을 분 단위 순서대로 위에서 아래로 쌓는다.
- 카드에는 `09:42`, 제목/본문 2줄, 작은 썸네일 또는 상태 표시가 있다.
- 카드 높이나 폭은 기록 가독성을 위한 크기이며 소요시간과 관계없다.
- 시간 열에 3개가 넘으면 우선 3개와 `기록 N개 더 보기`를 보여준다. 추가 기록은 시간 열의 확장 목록에서 모두 접근 가능해야 한다.
- 기록 없는 시간 열은 `기록 없음`을 표시한다. 업무가 없었다고 추정하지 않는다.
- 최초에는 선택한 기록이 있으면 그 시각, 없으면 당일 첫 기록이 보이게 이동한다. 기록이 없으면 09시 부근에서 시작할 수 있지만 근무 시작 시각으로 저장하지 않는다.
- 가로 스크롤바를 제공한다. 세로 휠을 예고 없이 가로 스크롤로 바꾸지 않는다. Shift+휠 이동은 추가 가능하다.
- 카드 클릭 → D01, 미니맵 위치 강조 → T01에서 동일 레코드 선택이 일관되게 이어져야 한다.

#### 금지

메모 시각 사이를 꽉 찬 막대로 연결하기, 그 길이를 집중시간으로 계산하기, 기록을 예쁘게 배치하려고 실제 시각을 조정하기, 하루 전체가 아닌 일부만 보여주고 전체 하루라고 표시하기.

### T03. 업무별 보기

- 선택한 날짜의 기록을 관련 WorkItem별로 묶는다.
- 업무 없는 메모는 `업무 미연결` 그룹으로 유지한다. 자동 추정 분류하지 않는다.
- 그룹 헤더: 업무명, 현재 상태, 해당 날짜 기록 수, 선택적 이슈 번호.
- 그룹 내부 기록은 시간순으로 표시한다.
- 현재 상태와 과거 시점의 상태를 혼동하지 않도록 현재 상태 배지에는 `현재`를 표시한다.
- 기본은 해당 날짜 기록만. `이 업무 전체 기록`은 별도의 날짜 범위 표시와 함께 펼친다.
- 프로젝트가 있는 경우 프로젝트는 업무 위의 보조 묶음이다. 프로젝트 선택 없이도 앱 전체를 사용할 수 있어야 한다.
- 프로젝트명만 있는 기록과 WorkItem에 연결된 기록을 데이터에서 구분한다.
- 프로젝트 선택 팝오버에 `프로젝트 만들기`를 제공한다. 이름은 공백 제외 1~40자로 제한한다.
- 프로젝트명 수정과 보관은 작은 관리 대화상자에서 처리한다. 보관한 프로젝트는 신규 연결 선택에서 숨기되 과거 기록/필터에서 찾을 수 있다.
- 프로젝트를 보관해도 업무·기록·첨부는 삭제하지 않는다. 별도의 프로젝트 관리 대시보드를 만들지 않는다.

### D01. 기록과 근거 상세

표시 순서: 유형/상태 → 제목·본문 → 기록 시각 → 사용자 지정 발생 시각(있을 때) → 연결 업무/프로젝트/이슈 → 첨부 → 관련 기록.

- UTC를 사용자에게 그대로 노출하지 않고 설정된 표시 시간대로 변환한다.
- `기록 시각`은 시스템 기록을 유지한다.
- 사용자가 과거 일을 나중에 적으면 `발생 10:00 · 기록 10:24`처럼 둘을 함께 표시한다.
- 일반 메모를 편집하면 `수정됨` 표시와 변경 이력을 제공한다.
- 생성/완료/재열기/취소 이벤트 본문을 자유 편집해서 과거 사실을 바꾸는 기능은 제공하지 않는다. 추가 설명은 연결 메모로 남긴다.
- 이미지 썸네일 클릭 시 앱 내부 확대 뷰어: 맞춤/100%/확대/축소/닫기.
- 비이미지 파일은 파일명·크기·종류, 저장된 사본 위치 열기 또는 명시적 외부 열기만 제공한다.
- PDF/Office/HTML을 임의 WebView로 렌더링하거나 파일 안의 스크립트를 실행하지 않는다.
- 지원하지 않는 미리보기는 `이 형식은 미리보기를 지원하지 않습니다`라고 표시한다.
- 파일 누락이면 `첨부파일을 찾을 수 없습니다`를 표시하되 메모 전체가 사라지지 않게 한다.
- 링크는 사용자가 눌렀을 때만 기본 브라우저로 연다. 자동 메타데이터 조회·제목 수집은 없다.
- 일반 메모의 `휴지통으로 이동`에는 실행 취소를 제공한다. 완료 처리를 삭제 버튼으로 대체하지 않는다.

### W01. 전체 할 일

- `[진행 중] [완료] [취소]` 탭.
- 작업 제목은 필수, 설명·프로젝트·이슈는 선택이다.
- 제목 공백만 입력은 저장 금지. 최대 길이를 200자로 제한하고 안내한다.
- 완료/재열기/취소는 8장의 상태 규칙을 따른다.
- 별도 자동 우선순위·기한 알림·반복 할 일은 V1에 넣지 않는다.
- 취소는 `하지 않기로 한 일`이다. 완료 수에 넣지 않는다.
- 업무명을 변경해도 과거 생성/완료 이벤트의 제목 스냅샷은 바뀌지 않는다.
- 연결된 메모와 첨부를 연쇄 삭제하는 버튼을 만들지 않는다.

### Q01. 검색

- 검색 대상: 메모 제목/본문, 업무명, 파일 원래 이름, 수동 이슈 번호.
- 250~300ms 디바운스. 이전 검색 결과가 늦게 도착해 최신 검색어 결과를 덮지 않게 한다.
- 결과에는 날짜·시각·짧은 발췌·첨부 유무를 표시한다.
- 날짜 범위와 프로젝트 필터를 선택할 수 있다.
- 결과 선택 → 원래 날짜 타임라인에서 해당 기록 선택 + D01 표시.
- `%`, `_`, 작은따옴표 등이 쿼리를 깨뜨리지 않게 파라미터 바인딩과 검색용 이스케이프를 적용한다.
- 한국어 부분 문자열 검색을 실제로 테스트한다. V1은 검증된 단순 검색으로 충분하다. 별도 검색 서버·벡터 DB는 없다.
- 초안, 휴지통 기록은 기본 검색에서 제외한다.

### R01. 하루 정리·내보내기

AI 요약이 아니라 사용자가 남긴 기록을 재조합하는 화면이다.

- 선택 날짜와 표시 시간대를 상단에 명시한다.
- 완료한 업무, 메모, 첨부·이슈 근거를 확인한다.
- 내보낼 기록은 체크로 선택한다. 최초에는 모두 미선택이며 `전체 선택`을 제공한다.
- 첨부파일 포함은 별도 기본 OFF 옵션이다.
- 미선택 기록에 딸린 첨부를 몰래 포함하지 않는다.
- `선택 내용 미리보기`에서 텍스트와 포함 첨부 목록을 확인한다.
- 버튼: `텍스트 복사`, `Markdown 패키지 저장`. 선택 0개이면 비활성화하고 선택을 안내한다.
- 파일 저장 대화상자 취소는 오류가 아니다. 원래 선택 상태를 유지한다.
- 복사는 실제 클립보드 쓰기 성공 후에만 성공 표시한다.
- 패키지는 `report.md`, `attachments/`, 선택 기록 정보용 `manifest.json`을 ZIP으로 묶는다.
- Markdown 이미지/파일 링크는 패키지 내부 상대 경로로 생성한다. 로컬 전체 경로를 보고서에 노출하지 않는다.
- 기본 문구는 완료/관찰/진행 내용을 원문에 근거해 배열한다. 사용자에게서 나오지 않은 원인·성과·시간을 만들어내지 않는다.
- `Jira에 등록 완료` 같은 문구는 없다. 이 단계는 복사 또는 로컬 파일 저장이다.
- 보고서는 당시 내보내기의 사본이다. 이후 앱 내용 편집이 이미 내보낸 파일을 자동 변경하지 않는다.

### C01. 설정·백업·휴지통

설정 그룹: 창 표시, 단축키, 시작 동작, 표시 시간대, 데이터/백업, 정보.

- 항상 위 ON/OFF, 마지막 창 위치 복원, 로그인 시 실행 OFF 기본.
- 단축키 변경 전 새 조합의 등록 가능 여부를 검증하고 실패하면 기존 조합을 유지한다.
- 저장 위치·데이터 크기·최근 성공 백업 시각 표시.
- 데이터 폴더 열기, 백업 만들기, 백업 복원.
- 휴지통: 삭제된 일반 메모 복원, 개별 영구 삭제, 경고 후 비우기.
- 자동 영구 삭제와 자동 클라우드 백업은 없다.
- 앱 자체 파일 암호화가 없다는 사실과 내보내기·백업도 민감 정보를 포함한다는 점을 표시한다.
- 사용자 데이터 전체 초기화는 별도 위험 동작이다. 일반 설정 초기화와 섞지 않는다.

## 7. 시간·기록·첨부의 데이터 모델

복잡한 이벤트 소싱 프레임워크는 도입하지 않는다. 다만 상태 변경 이력을 별도 Entry로 남겨 타임라인을 재구성할 수 있게 한다.

### 기본 테이블

```text
projects
  id, name, created_at_utc, archived_at_utc?

work_items
  id, title, description?, status(open/completed/cancelled), project_id?
  issue_key?, issue_url?
  created_at_utc, updated_at_utc, completed_at_utc?, version

entries
  seq INTEGER PRIMARY KEY AUTOINCREMENT
  id UNIQUE, request_id UNIQUE
  kind(note/task_created/task_completed/task_reopened/task_cancelled)
  work_item_id?, project_id?
  title_snapshot, body
  recorded_at_utc, occurred_at_utc
  occurred_time_source(recorded/user)
  recorded_offset_minutes
  issue_key?, issue_url?
  reverses_entry_id?
  updated_at_utc?, deleted_at_utc?

entry_revisions
  id, entry_id, changed_at_utc
  previous_title, previous_body, previous_occurred_at_utc
  previous_project_id?, previous_work_item_id?
  previous_issue_key?, previous_issue_url?
  previous_attachment_ids_json

attachments
  id, original_name, stored_relative_path
  media_type, byte_size, sha256, created_at_utc
  thumbnail_relative_path?

entry_attachments
  entry_id, attachment_id, sort_order

work_item_revisions
  id, work_item_id, changed_at_utc, previous_values_json

drafts
  id, mode(note/task), body, work_item_id?, project_id?
  staging_attachments_json, updated_at_utc

settings
  key, value_json

schema_migrations
  version, applied_at_utc
```

### 스키마 규칙

- GUID 계열 식별자를 사용한다. Entry 정렬의 동률 해소는 `seq`다.
- 시각 저장 형식은 하나로 통일한다. 예: UTC ISO 8601 고정 정밀도. 혼합 형식으로 문자열 정렬하지 않는다.
- `recorded_at_utc`는 앱에서 최초 성공 저장 시점에 설정하고 이후 수정하지 않는다.
- 사용자 발생 시각 미지정 시 `occurred_at_utc = recorded_at_utc`다.
- 일반 메모에서만 발생 시각을 수정할 수 있다. 변경 전 값은 revision에 남긴다.
- 생명주기 이벤트의 발생 시각은 실제 앱 작업 시각이다. 과거 완료를 꾸며내는 편집을 제공하지 않는다.
- DB 외래 키와 필요한 인덱스를 설정한다. 시간순 조회 `(occurred_at_utc, seq)`, 업무 조회 `(work_item_id, occurred_at_utc)`, 첨부 관계 인덱스를 둔다.
- 모델에 WPF ImageSource 같은 표시 객체를 저장하지 않는다.
- 이미지 본문을 DB BLOB으로 넣지 않는다. 파일은 앱 관리 폴더에 두고 상대 경로만 저장한다.
- 원본 파일의 위치를 영구 의존성으로 삼지 않는다.
- `request_id`는 동일 저장 요청 재시도 동안 유지한다. 성공 결과를 받지 못한 요청의 재시도로 중복 기록이 생기면 안 된다.
- 작업 이름 변경·메모 편집·첨부 교체는 필요한 이전 값을 남긴다. 업무 완료 과거 제목은 제목 스냅샷으로 보존한다.
- SHA-256은 파일 누락·변경 확인 수단일 뿐, 로그 전체가 법적 증거이거나 위조 불가능하다는 보장이 아니다.

### 날짜 투영

- 표시 시간대는 최초 PC 설정을 기본값으로 저장하고 C01에서 확인·변경한다.
- 날짜 D 조회는 해당 시간대의 D 00:00 이상, D+1 00:00 미만을 UTC로 변환해 수행한다.
- UTC 날짜로 바로 그룹핑하지 않는다.
- 동일 시각에는 seq 순서를 사용한다.
- DST가 있는 시간대를 지원할 때 없는 시각은 오류로 안내하고, 두 번 존재하는 시각은 오프셋을 명시해 구분한다. 임의 보정하지 않는다.
- 시간대 변경은 저장된 UTC를 바꾸는 작업이 아니라 표시·날짜 그룹을 다시 계산하는 작업이다.
- 캡처 EXIF, 파일 수정일을 메모 기록 시각으로 몰래 대체하지 않는다.

## 8. 상태 전이·집계·동기화 규칙

### 8.1 업무 상태 전이

| 현재 | 명령 | 결과 | 타임라인 |
|---|---|---|---|
| 없음 | 생성 | open | task_created 1개 |
| open | 완료 | completed | task_completed 1개 |
| completed | 다시 열기/완료 실행 취소 | open | task_reopened 1개 |
| open | 취소 | cancelled | task_cancelled 1개 |
| cancelled | 다시 열기 | open | task_reopened 1개 |
| completed | 완료 재요청 | 유지 | 추가 이벤트 없음 |
| open | 다시 열기 재요청 | 유지 | 추가 이벤트 없음 |
| cancelled | 취소 재요청 | 유지 | 추가 이벤트 없음 |

완료된 업무를 곧바로 취소로 바꾸려면 먼저 다시 열어야 한다. UI도 이 순서를 따른다.

### 8.2 완료 명령의 원자성

```text
CompleteWorkItem(id, expectedVersion, requestId):
  DB 트랜잭션 시작
  같은 requestId 결과가 있으면 기존 성공 결과 반환
  현재 업무와 version 확인
  이미 completed면 중복 이벤트 없이 현재 결과 반환
  open이 아니거나 version 충돌이면 화면 갱신을 요청하는 결과 반환
  completed 상태와 completed_at_utc 설정, version 증가
  같은 트랜잭션 안에서 task_completed Entry 삽입
  커밋
  커밋 성공 후 열린 창들에 변경 사실 알림
```

- 상태 변경과 이벤트 삽입 중 하나만 성공하면 안 된다.
- 재열기 이벤트는 해당하는 마지막 완료 이벤트를 `reverses_entry_id`로 연결할 수 있다.
- 다시 열기는 현재 상태의 `completed_at_utc`를 NULL로 되돌린다. 과거 완료 시각은 Entry에 남는다.
- 실패 시 체크박스·목록을 이전 상태로 돌리고 오류를 표시한다.
- 저장 성공 전에 활성 TODO를 영구적으로 제거하지 않는다.
- UI의 버튼 비활성화만으로 중복 방지를 해결하지 않는다. DB/서비스 계층에서도 처리한다.
- 완료 이벤트는 이후 업무 제목 변경으로 덮어쓰지 않는다.

### 8.3 여러 창의 일관성

한 프로세스·한 데이터 저장소를 사용한다. 플로팅 창과 메인창이 별도 TODO 사본을 유지하지 않는다.

DB 커밋 후 앱 내부 변경 알림을 보내고 필요한 조회만 갱신한다. 각 창이 100ms 주기로 DB 전체를 폴링하는 방식은 금지한다. 선택 중인 기록, 입력 초안, 스크롤 위치를 무조건 초기화하지 않는다.

### 8.4 하루 집계의 정의

날짜 헤더의 집계는 '선택 날짜 전체' 기준이다. 보기 필터를 적용해도 헤더 숫자는 유지하고 목록에는 별도로 `표시 X개 / 전체 Y개`를 표시한다.

- 기록 N개: 그 날짜에 투영되는 휴지통 제외 Entry 수. 메모·생성·완료·재열기·취소를 포함하고 첨부 자체를 별도 Entry로 중복 계산하지 않는다.
- 첨부 K개: 그 날짜의 휴지통 제외 Entry에 연결된 고유 attachment_id 수.
- 완료 업무 M개: 선택 날짜 종료 시점(오늘은 현재 시점)까지의 각 업무 최신 생명주기 이벤트가 task_completed이며, 그 최신 완료 이벤트가 선택 날짜 안에 있는 고유 업무 수.
- 같은 날 완료 → 다시 열기 → 재완료는 최종 완료 업무 1개다.
- 같은 날 완료 → 다시 열기로 끝나면 완료 업무 0개다.
- 다음 날 다시 열었다고 전날 종료 시점의 집계를 소급해서 바꾸지 않는다. 상세에는 현재 다시 열림을 별도로 표시할 수 있다.
- 오늘 완료 목록은 단순 `work_items.status`만 조회해서 만들지 않는다. 과거 날짜 집계가 틀어지지 않게 이력에서 계산한다.
- 기록 수나 첨부 수를 근무시간·성과로 환산하지 않는다.

집계는 Core 서비스로 분리하고 위 사례를 단위 테스트한다.

## 9. 저장·초안·파일 처리

### 9.1 기본 저장 위치

```text
%LOCALAPPDATA%/FlowNote/
  live/
    flownote.db
    attachments/
    thumbnails/
    staging/
  demo/
  restore-staging/
  backup-history.json
  diagnostics/
```

운영 DB를 Git 저장소, 실행 파일 폴더, 임의 네트워크 공유, 자동 동기화 폴더 안에 만들지 않는다. 실행 파일 업데이트가 사용자 데이터를 덮어쓰지 않게 한다.

### 9.2 DB 실행

- SQL 값은 모두 파라미터 바인딩한다.
- 매 연결에 외래 키 검증을 활성화한다. WAL·busy timeout·동기화 설정을 명시한다.
- `.NET Async` 이름의 SQLite 메서드만 호출하고 UI 비차단 처리가 되었다고 생각하지 않는다.
- `DatabaseExecutor` 같은 작은 서비스를 통해 DB 작업을 UI 스레드 밖에서 수행한다. 단일 쓰기 실행 경로와 제한된 큐/직렬화를 사용한다.
- 한 연결 객체를 여러 스레드에서 동시에 공유하지 않는다.
- UI 컬렉션 업데이트만 Dispatcher에서 수행한다.
- 오류를 삼키거나 DB가 열리지 않는다고 새 빈 DB로 덮어쓰지 않는다.

### 9.3 초안

- 입력 후 500ms 정도 디바운스하여 초안을 저장한다.
- 초안은 타임라인 기록이 아니다. 저장 버튼/Ctrl+Enter 성공 시에만 Entry가 된다.
- 초안 저장 실패와 Entry 저장 실패를 구분한다.
- 초안 첨부는 staging에 보관하고 저장 성공 후 정식 경로로 이동한다.
- 사용자에게 표시한 '초안 보관됨' 시점까지는 재실행 후 복구되어야 한다.
- 아직 디바운스가 끝나지 않은 입력까지 강제 종료에서 절대로 보존된다고 보장하지 않는다.
- 정상 숨김/종료 시 초안 저장을 시도하고 실패하면 계속 종료할지 사용자에게 알린다.
- 저장 성공 뒤에만 입력칸과 초안을 비운다.

### 9.4 첨부 추가

입력: 사용자가 직접 수행한 Ctrl+V, 파일 선택, 드래그앤드롭.

- 이미지 붙여넣기는 가능하면 PNG 사본으로 저장한다.
- 클립보드는 붙여넣기 동작 때만 읽는다.
- 일시적인 클립보드 접근 실패는 제한된 재시도 후 안내하고 기존 입력은 유지한다.
- 사용자 선택 파일은 앱 저장소로 복사한다. 원본 이동/삭제는 하지 않는다.
- 기본 제한: 파일당 25MB, 한 기록 최대 10개. 제한은 중앙 상수로 관리하고 UI에 설명한다.
- 이미지 미리보기는 PNG/JPEG부터 확실히 지원한다. 그 외는 일반 첨부로 저장하고 지원하지 않는 미리보기를 약속하지 않는다.
- 실행 파일·스크립트·바로가기 같은 형식은 V1 첨부에서 거부한다. 목록과 예외 처리를 문서화한다. 파일 확장자 검사만으로 안전성이 보장된다고 설명하지 않는다.
- 일반 문서/로그/압축 파일은 저장할 수 있어도 자동 실행·매크로 실행·압축 해제하지 않는다.
- 과도한 이미지 해상도·디코드 실패를 처리한다. 썸네일을 위해 원본 전체 해상도를 UI에 동시에 올리지 않는다.
- 원래 파일명은 메타데이터로 보존하고 물리 파일명은 GUID 기반 안전 이름을 사용한다.
- 썸네일은 파생 캐시다. 없으면 재생성하고 원본을 삭제하지 않는다.

### 9.5 파일과 DB의 일관성

파일 시스템 작업은 SQLite 트랜잭션과 한 몸이 아니므로 별도 실패 복구를 설계한다.

```text
요청 식별자 생성
 → staging에 파일 복사, 크기/해시 확인
 → 앱 관리 첨부 경로에 안전하게 이동
 → DB 트랜잭션으로 Entry + Attachment + 관계 저장
 → 커밋 성공
 → 입력 초기화 / 화면 갱신
```

- 파일 복사 실패: Entry 전체 저장을 실패 처리하고 초안을 보존한다.
- DB 커밋 실패: 사용자의 입력을 보존하고 파일은 재시도 또는 고아 파일 정리 대상임을 표시한다.
- 재시작 정리 시 DB·초안·revision·백업 작업에서 참조 중인 파일은 삭제하지 않는다.
- 일반 메모 편집으로 제거한 첨부는 revision에서 참조할 수 있으므로 즉시 물리 삭제하지 않는다.
- 파일을 찾을 수 없는 경우 데이터를 조용히 삭제하거나 저장 성공처럼 표시하지 않는다.

## 10. 백업·복원·삭제

### 백업

- 실행 중 DB 파일 하나를 단순 복사해서 정상 백업이라고 하지 않는다.
- Microsoft.Data.Sqlite의 백업 API 등 일관된 DB 스냅샷 방식을 사용한다.
- 스냅샷 DB가 참조하는 첨부와 revision 첨부까지 함께 수집한다.
- 첨부는 저장 후 불변 사본으로 다루고, 백업 중 물리 정리를 중지해 DB·첨부의 시점 불일치를 피한다.
- 백업 API 실행 중 쓰기가 지연될 수 있으므로 UI에 상태를 표시하고 사용자의 입력을 잃지 않는다.
- ZIP에는 DB, 첨부, 버전·해시·파일 목록 manifest를 포함한다. 썸네일은 재생성 가능하므로 필수 아님.
- 임시 ZIP으로 완성한 뒤 검증 성공 시 최종 이름으로 바꾼다.
- 같은 디스크 백업은 장치 고장에 대한 완전한 보호가 아니다. 회사가 허용한 별도 위치에 사용자가 저장할 수 있게 한다.
- 자동 보존 정책은 V1에 넣지 않는다. 수동 백업을 확실히 구현한다.

### 복원

- ZIP 경로 탈출(`../`, 절대 경로), 과도한 확장 크기, 잘못된 manifest, 지원 불가능한 DB 버전을 거부한다.
- 임시 복원 폴더에 풀고 파일 해시·DB 무결성·참조를 검사한다.
- 검증 전 현재 데이터를 덮어쓰지 않는다.
- 복원은 덮어쓰기 방식이며 병합이 아님을 표시한다. 현재 데이터의 안전 사본을 먼저 확보한다.
- V1은 `복원 준비 후 앱 종료 → 다음 시작 때 적용` 방식으로 단순화할 수 있다.
- 다음 시작 시 DB 연결을 열기 전에 복원을 적용한다. DB 연결/풀과 WAL 파일을 열린 상태로 교체하지 않는다.
- 폴더 교체 중 중단되었을 때 기존 또는 검증된 복원본으로 돌아갈 수 있도록 복원 단계 marker와 이전 폴더를 보존한다.
- 중단 복구 테스트까지 통과해야 '복원 지원'이라고 표시한다.

### 삭제

- 완료는 삭제가 아니다.
- 일반 메모 삭제는 휴지통 이동이며 모든 보기/집계에서 제외한다.
- 복원하면 원래 시간 위치에 다시 나타난다.
- 영구 삭제는 명시적 경고 후 실행한다. 공유 첨부는 다른 활성 기록·revision이 참조하면 삭제하지 않는다.
- 업무 생명주기 이벤트는 V1에서 개별 삭제 기능을 제공하지 않는다. 이 정책은 UI와 안내에서 드러내야 한다.
- 앱 데이터 초기화와 이미 내보낸 보고서·외부 백업 삭제는 서로 다르다. 외부 사본도 자동 삭제됐다고 주장하지 않는다.

## 11. Jira·외부 도구·보안 범위

### V1 수동 연결

- WorkItem/Entry에 이슈 번호와 HTTP/HTTPS URL을 저장할 수 있다.
- 이슈 번호는 예시 `DEV-1234`처럼 표시하되 Jira의 모든 프로젝트 키 규칙을 임의 정규식 하나로 제한하지 않는다. 사용자가 입력한 값으로 취급한다.
- URL을 입력해도 외부 요청으로 유효성을 확인하지 않는다.
- URL 스킴은 HTTP/HTTPS만 허용한다. `file:`, `javascript:`, shell 명령 스킴은 차단한다.
- 사용자 클릭 시 기본 브라우저로 연다. 앱 내 로그인·SSO 쿠키 추출은 하지 않는다.
- 필요하면 설정된 Jira base URL과 이슈 번호로 링크를 구성하되 주소 인코딩과 경로 결합을 검증한다.
- 화면 이름은 `이슈 연결` 또는 `링크 연결`이다. `Jira 동기화됨`이 아니다.
- API 제한을 브라우저 자동 클릭·스크래핑·토큰 추출로 우회하지 않는다.
- 이후 API 연동은 별도 승인 후 설계한다. 현재 명세에 서버 주소·토큰 보관 코드를 미리 넣지 않는다.

### 오프라인과 보안

- 앱 자체가 부팅·메모·검색·종료 과정에서 외부 서버로 데이터를 보내지 않는다.
- 분석 SDK, 광고, 원격 폰트, 외부 AI, 자동 업데이트 확인, 원격 오류 수집을 추가하지 않는다.
- 링크/파일을 명시적으로 열어 외부 프로그램에 넘기는 행동은 사용자가 구별할 수 있어야 한다.
- 진단 로그에는 메모 원문, 첨부 내용, 인증 정보, 전체 민감 경로를 넣지 않는다.
- 로컬 파일 저장은 암호화나 회사 승인과 동의어가 아니다. 암호화 필수 정책이 확인되면 현재 비암호화안은 배포 보류한다.
- 인증서·서명·권한 정책을 우회하기 위해 보안 프로그램 비활성화를 안내하지 않는다.
- 항상 위 기능이 UAC 보안 화면·잠금 화면·다른 모든 topmost 창보다 무조건 위에 뜬다고 약속하지 않는다.

## 12. 데스크톱 품질·성능·접근성

### 창·OS 동작

- 단일 사용자 데이터 경로에 대해 단일 인스턴스만 실행한다.
- 두 번째 실행은 기존 인스턴스의 창을 열고 종료한다. DB 사본을 만들지 않는다.
- 창 위치 저장에는 모니터 식별과 DIP/화면 좌표 변환을 고려한다.
- 보조 모니터가 사라지면 현재 사용 가능한 작업 영역 안으로 이동한다.
- 100/125/150/200% 배율에서 입력·체크박스·시각·썸네일이 잘리지 않는지 검수한다.
- 상단 고정과 포커스 활성화를 분리한다. 주기적 `Activate()` 호출은 금지한다.
- 절전/복귀, 자정 경과 후에도 날짜와 목록이 일관되게 유지되어야 한다.
- 기본 메인창은 일반 창이며 항상 위가 아니다. 플로팅 창에만 사용자의 핀 설정을 적용한다.
- 모달 대화상자가 플로팅 창 뒤에 숨지 않도록 소유자와 z-order를 실제 테스트한다.

### 성능 목표 — 아직 측정 결과가 아님

기준 환경을 문서화한다: 예시 Windows 11 x64, 4코어 이상, RAM 16GB, SSD. 더 좋은 개발 PC의 결과를 일반 보장으로 표현하지 않는다.

데이터 fixture: 텍스트 이벤트 10,000개, 첨부 이미지 1,000개. 합성 자료만 사용한다.

초기 목표:

- 일반 메모 저장 후 UI 반영 p95 300ms 이내.
- 사용 중인 앱의 기록창 호출 p95 200ms 이내.
- 하루 100개 기록 조회 p95 500ms 이내.
- 검색 p95 500ms 이내(디바운스 제외).
- 유휴 60초 평균 CPU 1% 이하를 목표로 측정.
- 유휴 메모리는 250MB 이하를 초기 목표로 측정하되 실제 측정 방식·조건과 원인을 기록한다.

이 수치는 목표다. 검증 없이 충족됐다고 주장하지 않는다. 최초 기준 측정 후 합리적 변경이 필요하면 수치·근거를 보고하고 승인받는다.

구현 원칙:

- 가상화된 목록, 필요한 날짜 범위 조회, 작은 썸네일, 제한된 이미지 캐시.
- UI 가상화와 데이터 조회 제한을 별개로 점검한다.
- 가상화 목록을 바깥 ScrollViewer로 감싸서 가상화가 무효가 되지 않게 한다.
- DB·파일 해시·압축·이미지 디코드로 UI 스레드를 막지 않는다.
- 기록마다 모든 창 전체를 다시 만들지 않는다.
- CPU를 쓰는 주기적 장식·고빈도 폴링을 넣지 않는다.

### 접근성과 한국어 입력

키보드 Tab 순서, 보이는 포커스, 버튼 접근성 이름, 상태 텍스트, 기본 고대비/화면 확대 동작을 확인한다. 한글 조합·받침 입력·조합 확정 Enter·붙여넣기를 Windows에서 실제 테스트한다.

## 14. 작업 방식: 역량이 낮은 Worker도 놓치지 않도록

전체 프로젝트를 한 번에 구현하지 않는다. `02_PHASE_BY_PHASE_PROMPTS.md`의 단계를 한 번에 하나씩 실행한다.

각 단계 시작 전:

1. 해당 단계 목표와 관련 명세만 다시 읽는다.
2. 현재 소스와 `PROGRESS.md`를 확인한다. 이미 완료된 코드를 새로 만들지 않는다.
3. 수정할 파일과 검수 항목을 정한다.
4. 되돌리기 큰 변경이 아니면 실제 구현부터 진행한다.

각 단계 종료 전:

1. 관련 자동 테스트 실행.
2. 가능한 빌드와 실제 실행 확인.
3. 해당 화면·행동의 증거 확보.
4. 실패를 수정한 뒤 다시 실행.
5. `PROGRESS.md`에 통과/실패/미검증과 다음 한 단계를 기록.

금지:

- 명세를 다시 길게 설명하고 구현을 끝내는 것.
- 실제 저장소 대신 mock 데이터 화면만 납품하는 것.
- 테스트를 실행하지 않고 '정상 동작합니다'라고 말하는 것.
- 기능이 실패하는 테스트를 삭제하거나 assertion을 약하게 바꿔 통과시키는 것.
- UI를 마무리한다는 이유로 핵심 타임라인을 단순 TODO 보드로 바꾸는 것.
- 이전 단계와 무관한 대규모 리팩터링, 프레임워크 교체.
- 테스트·빌드 오류가 있는 상태에서 다음 큰 기능을 계속 추가하는 것.
- 확인하지 않은 임의 npm/NuGet 패키지와 존재하지 않는 API를 사용하는 것.

실행 환경이 Windows GUI를 제공하지 않는 경우 Core/저장 테스트 등 가능한 작업은 수행한다. 하지만 실제 창 표시·IME·DPI·트레이·글로벌 단축키 검증은 `미검증: Windows 실행 환경 필요`로 남긴다. Linux에서 코드가 빌드되었다는 이유로 Windows UI 검수를 통과시켜서는 안 된다.

컨텍스트가 부족해지면 `PROGRESS.md`에 상태를 저장한다. 다음 실행에서는 이어서 한 단계만 수행한다.

## 15. 검수와 완료의 정의

`03_ACCEPTANCE_TESTS.md`의 각 테스트를 다음 중 하나로 표시한다.

- PASS: 실제 실행 증거 있음.
- FAIL: 실제 실패 및 재현 절차 있음.
- NOT RUN: 실행하지 못함. 이유 있음.
- BLOCKED: 외부 승인/환경 의존. 무엇이 필요한지 있음.

`NOT RUN`과 `BLOCKED`를 PASS로 세지 않는다.

각 UI 화면에 대해 기본·빈 상태·로딩/저장 중·오류·긴 텍스트·선택 상태를 확인한다. 설정·버튼·내보내기 경로가 장식으로 남아 있으면 미완료다.

### 납품물

- 전체 소스, 솔루션, 버전 고정·잠금 파일.
- DB 스키마와 버전 migration.
- 단위/통합 테스트와 실제 실행 결과.
- 합성 데모 데이터 생성 방법. 일반 모드와 분리.
- Windows x64 실행 패키지. 베타는 self-contained 폴더 ZIP 기준으로 한다.
- 사용자 설치 권한 정책을 우회하지 않는다. ZIP 실행도 사내 허용 여부를 별도 확인한다.
- `build.ps1`, `test.ps1`, `publish.ps1`.
- 사용자 실행·백업·복원·삭제 안내.
- 실제 앱 캡처와 UI 검수표.
- 알려진 문제·미검증 조건·제외 범위.
- 사용한 외부 라이브러리/아이콘의 라이선스 목록.

예시 publish 명령은 선택한 프로젝트 경로와 SDK에서 실제 실행해 검증한다.

```powershell
dotnet restore FlowNote.sln --locked-mode
dotnet build FlowNote.sln -c Release --no-restore
dotnet test FlowNote.sln -c Release --no-build
dotnet publish src/FlowNote.Desktop/FlowNote.Desktop.csproj `
  -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=false -p:PublishTrimmed=false `
  -o artifacts/win-x64
```

잠금 파일 최초 생성은 `--locked-mode` 이전 준비 단계에서 한다. 아직 파일이 없는데 locked restore가 실패했다고 잠금 정책을 제거하지 않는다.

공개 유료 배포를 위해서는 코드 서명·배포 패키지·업데이트 경로·런타임 패치 공급·라이선스/결제 정책·지원 문서를 별도 확정해야 한다. 첫 베타 프로그램 납품을 곧바로 공개 판매 준비 완료로 표시하지 않는다.

### 최종 결과 보고 형식

```text
구현 완료 범위:
실제 실행 환경 / 버전:
빌드 명령과 결과:
테스트 PASS / FAIL / NOT RUN:
주요 UI 캡처 경로:
실행 패키지 경로:
데이터 저장 위치 / 백업 복원 검증:
알려진 문제:
사용자 결정이 필요한 항목:
다음 한 단계:
```

제품의 최종 판단 기준은 하나다.

> 사용자가 잠깐 남긴 기록과 완료한 일을, 나중에 하루의 흐름과 근거로 다시 확인할 수 있는가?

이 기준을 충족하지 못하면 화면이 예뻐도 완료가 아니다.

# 검수 시나리오와 결과 템플릿

이 파일은 **검수 계획**이다. 현재 패키지는 앱을 구현하거나 아래 테스트를 실행한 결과물이 아니다.

각 행의 초기 상태는 `NOT RUN`이다. Worker는 실제 실행 후 `PASS / FAIL / NOT RUN / BLOCKED` 중 하나와 증거 경로를 기입한다. PASS는 예상 결과가 실제로 관찰된 경우에만 사용한다.

보안/장애 주입은 합성 데이터와 임시 저장소에서 수행한다. 회사의 실제 데이터·다른 프로그램 설정을 파괴하여 시험하지 않는다.

|---|---|---|---|---|

# Worker 최초 실행 프롬프트

아래 구분선부터 복사하여 전달한다. 이 파일만 전달하고 첨부 명세가 자동으로 전달되었다고 가정하지 않는다.

---

당신은 FlowNote Desktop의 구현 담당자다.

목표는 예쁜 목업이나 일반 TODO 앱이 아니라, 사용자가 남긴 메모·이미지·파일·완료 이력을 시간순으로 묶어 **하루의 흐름과 근거를 확인하는 실제 데스크톱 앱**이다.

내가 제공한 폴더에서 다음을 먼저 읽어라.

1. `00_READ_FIRST.md`
2. `01_MASTER_IMPLEMENTATION_PROMPT.md`
3. `02_PHASE_BY_PHASE_PROMPTS.md`의 공통 규칙 및 PHASE 00
4. `03_ACCEPTANCE_TESTS.md`
5. 참고 이미지 3장

파일이 보이지 않으면 확인한 경로와 누락 파일을 말하라. 읽지 않은 명세를 읽었다고 주장하지 마라. 참고 이미지가 접근 불가하면 텍스트 기반 준비는 진행할 수 있으나 시각 참조 검수는 미검증으로 남겨라.

이번 실행에서는 **PHASE 00만 수행하라.** 아직 전체 기능을 만들지 마라.

현재 잠정안은 Windows 11 x64 / C# / .NET 10 LTS / WPF / 로컬 SQLite이다. 발주자가 확정한 결정이 있으면 그 결정을 우선한다. 기존 프로젝트가 있으면 구조를 먼저 조사하고 프레임워크를 임의 교체하지 마라.

이번 단계에서 환경·현재 코드·의존성 버전·Windows GUI 실행 가능 여부를 확인하고, 명세와 결정·진행·검수 문서를 프로젝트 안에 준비하라. 비어 있는 프로젝트라면 최소한의 솔루션과 빌드·테스트 기반만 구성하라. 결과 없는 설계 보고서로 끝내지 마라.

반드시 지킬 제품 규칙:

- 플로팅 창은 입력 수단이고, 핵심 메인 화면은 하루 타임라인이다.
- TODO 완료는 삭제가 아니다. 활성 목록에서 숨기고 완료 Entry를 저장한다.
- 텍스트·이미지·파일·완료 이벤트는 동일한 하루 흐름 안에서 연결된다.
- 시간순·파노라마·업무별 보기는 동일한 데이터와 선택 상태를 공유한다.
- 기록 시각을 실제 작업 시작 시각으로 간주하지 마라. 기록 간격을 근무시간으로 계산하지 마라.
- API, AI, 클라우드, 화면·클립보드 상시 수집, 모바일 앱을 임의 추가하지 마라.
- 회사의 Jira REST API 제한을 우회하지 마라. V1 연결은 수동 이슈 번호/URL과 선택 내보내기다.
- 참고 이미지 속 지원 로고나 통계를 미구현 상태로 노출하지 마라.
- 이미지는 시각 참고일 뿐이다. 앱 화면은 실제 컨트롤로 구현해야 한다.

작업 원칙:

- 한 번에 한 단계만 수행한다.
- 관련 테스트가 실패하면 해당 기능을 고치고 다시 검사한다.
- 실행하지 않은 테스트, 보지 않은 화면을 통과했다고 보고하지 않는다.
- 환경상 Windows UI 실행이 불가능하면 가능한 Core/저장 테스트를 수행하고 UI 검수는 미검증으로 남긴다.
- 다음 작업자가 이어갈 수 있도록 `docs/PROGRESS.md`에 상태를 기록한다.

이번 실행 마지막에 아래만 보고하라.

```text
수행한 단계:
확인한 환경·기존 코드:

실제 수행한 명령과 결과:
PASS / FAIL / NOT RUN / BLOCKED:

다음에 수행할 한 단계:
```

'전체 완성', '정상 동작' 같은 표현은 실제 검증한 범위에만 사용하라.

# 기술 근거 — 공식 문서

확인일: 2026-09-14. 이 파일은 기술 선택의 근거이며 실제 구현/성능 검증 결과가 아니다. 특정 NuGet 패치 번호는 개발 시점에 다시 확인하고 고정한다.

## R1. WPF와 Windows 플랫폼

공식 문서는 WPF가 XAML, 데이터 바인딩, 스타일·템플릿을 제공하고 Windows에서만 실행된다고 설명한다. 따라서 이 패키지의 WPF 선택은 Windows 우선 출시라는 잠정 조건에 의존한다.

`https://learn.microsoft.com/en-us/dotnet/desktop/wpf/overview/`

## R2. .NET 지원 정책

확인 시점에 .NET 10은 LTS 활성 지원 계열이다. 지원 중 패치를 사용하고 재현 가능한 버전을 고정한다. Self-contained 배포에는 런타임도 포함되므로 이후 런타임 패치가 필요할 때 앱 패키지를 갱신할 책임이 있다.

`https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core`

## R3. Topmost의 의미

Topmost는 일반 창보다 높은 z-order를 뜻한다. 모든 topmost 창보다 무조건 위라는 의미가 아니다. 앱의 기능 설명과 검수 범위를 일반 데스크톱 창 기준으로 한정한다.

`https://learn.microsoft.com/en-us/dotnet/api/system.windows.window.topmost?view=windowsdesktop-10.0`

## R4. 상단 고정과 활성화의 분리

ShowActivated는 처음 창을 표시할 때 활성화 여부를 제어한다. 표시 전에 설정해야 하며 이후 사용자의 선택에 의한 활성화는 별도다. 이 속성 하나만으로 이후 모든 포커스 문제를 해결했다고 주장하지 않고 실제 동작을 검수한다.

`https://learn.microsoft.com/en-us/dotnet/api/system.windows.window.showactivated?view=windowsdesktop-10.0`

## R5. SQLite Async 주의점

Microsoft.Data.Sqlite의 ADO.NET Async 메서드는 동기 실행된다는 공식 제한이 있다. 무거운 DB 작업을 UI 스레드 밖에서 실행하고 연결·쓰기를 안전하게 관리해야 한다.

`https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/async`

## R6. SQLite 백업

BackupDatabase로 앱 실행 중 DB 백업이 가능하다. 문서는 백업 중 다른 연결의 쓰기가 차단될 수 있다는 점도 설명한다. 첨부파일은 DB 백업에 자동 포함되지 않으므로 앱 수준의 일관성 있는 패키징이 별도로 필요하다.

`https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/backup`

## R7. 전역 단축키

RegisterHotKey로 전역 단축키를 정의한다. 실패 반환과 이미 사용 중인 조합을 처리해야 한다. 키 입력 전체를 수집하는 구현은 필요하지 않다.

`https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey`

## R8. WPF 목록 성능

WPF의 UI 가상화·컨테이너 재사용을 확인하고, 가상화를 무력화하는 컨트롤 구조를 피한다. UI 가상화는 모든 데이터가 자동으로 지연 로드된다는 뜻이 아니므로 조회 범위 제한도 별도로 적용한다.

`https://learn.microsoft.com/en-us/dotnet/desktop/wpf/advanced/optimizing-performance-controls`

팔레트, 화면 크기, 타임라인 버킷, 파일 크기 제한, 집계 규칙, DB 모델, 단계 분할, 성능 목표는 이 제품을 위해 제안한 명세다. Microsoft가 이 제품의 UX·성능·보안을 보증한 것이 아니다.
