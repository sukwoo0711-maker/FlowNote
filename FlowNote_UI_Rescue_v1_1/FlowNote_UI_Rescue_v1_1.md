# FlowNote UI/UX 재작업 지시서 v1.1

상태: 제안하는 시각·상호작용 수정안. 기존 코드나 실행 프로그램을 수정·검증한 결과물이 아니다.
대상: 기존 FlowNote 데스크톱 프로젝트. 저장·완료 이력·첨부·보안 요구는 유지한다.
핵심: 플로팅 창은 빠른 입력 수단, 하루 타임라인은 제품의 중심 화면이다.

## 0. 기존 명세와의 관계

이 문서는 기존 전체 구현 명세를 폐기하는 문서가 아니다. UI 배치·표현·검수 순서에서 아래 변경을 우선한다. 데이터 보존, 기록 시각, 완료/재열기, 명시적 기록 저장, 초안 복구, 접근성, 오프라인·사내 정책은 기존 요구를 유지한다.

이번 UI 변경:
- 미선택 상태에서는 우측 상세 패널과 그 열을 접는다.
- 전역 탐색과 날짜 선택, 보기 전환을 분리한다.
- **플로팅 창 구조는 SUPERSEDED BY docs/FLOATING_CAPSULE_V2.md.** 하단 상시 할 일·360 DIP 세로 메모장·500 DIP 기본 높이를 유지하라는 구절은 폐기한다. 플로팅은 제목 없는 520×52 DIP 캡슐이며, 할 일은 사용자가 연 작은 패널에서만 작성한다.
- 디자인 프리뷰에는 격리된 fixture를 허용한다. 최종 납품은 실제 저장 흐름으로 검증한다.
- 기능 완료와 시각 승인, 사용성 검증을 각각 따로 기록한다.

앞선 생성 이미지는 분위기와 시간축·첨부 표현을 참고하는 자료다. 승인된 데스크톱 구현 기준 화면은 아직 없다. 이미지의 모바일 프레임, 홍보 문구, 배경 사진, 미지원 기능을 옮기지 않는다.

## 1. 담당자의 작업 규칙

전체 앱을 다시 만들지 않는다. 기존 저장소의 프레임워크·버전·View·ViewModel·테마·컨트롤·바인딩을 먼저 조사한다. 스크린샷만 보고 코드 원인을 확정하지 않는다.

처음 확인할 것:
1. 현재 작업 단계와 기존 테스트 결과. 미완성 프로토타입인지 최종 납품인지 구분한다.
2. 메인창과 플로팅 창의 실제 소스 경로.
3. 공통 스타일이 두 창에 모두 적용되는지, 지역 스타일이 덮어쓰는지.
4. 시간순/업무별 템플릿과 선택 바인딩이 섞여 있는지.
5. 메모 입력 위 안내문구가 실제 입력과 겹치는 재현 조건.
6. 우측 글자 잘림이 실제 앱 문제인지 캡처 잘림인지.
7. UI를 실제로 실행하고 캡처할 수 있는 Windows 환경 유무.

보존할 것:
- DB, 사용자 파일, 초안, 기록/발생 시각, 완료·재열기·취소 이력.
- 기존 서비스 및 명령 계약, 다중 창 동기화, IME/키보드 조작.
- 기존 테스트. 실패 테스트를 삭제하거나 약화하지 않는다.

금지:
- 프레임워크 교체, 저장 계층 전면 리팩터링, 데이터 초기화.
- AI, API 연동, 타이머, 통계 대시보드 등 새 제품 기능 추가.
- 포스터/생성 이미지/HTML 목업을 실행 중인 앱 화면으로 제출.
- 정적 스크린샷을 배경으로 깔고 투명 버튼을 얹는 구현.
- 실제 사용자 데이터를 공개 캡처에 사용.
- 코드와 실제 화면을 확인하지 않고 ‘디자인 완료’ 선언.

## 2. 현재 화면에서 해결할 문제

아래는 제공된 캡처에서의 관찰이다. 클릭 결과와 실제 내부 원인은 실행/코드로 확인한다.

| 관찰 | 이번 수정 목표 |
|---|---|
| 오늘/시간순/업무별이 같은 메뉴 계층 | 날짜와 보기 모드를 분리하고 선택 상태를 일치시킨다. |
| 파노라마 진입 경로가 캡처에서 보이지 않음 | 시간순/파노라마/업무별을 중앙 헤더에서 노출한다. 구현 여부는 코드로 확인한다. |
| 시간과 카드가 있으나 축·노드 표현이 보이지 않음 | 시간축을 가진 사건 목록으로 구현한다. |
| ‘업무 미연결’과 ‘그룹’이 큰 카드로 노출 | 시간순 보기에서는 분류 헤더를 없앤다. 업무별 보기에서만 의미 있는 그룹 헤더를 쓴다. |
| 제목과 본문이 같은 문장으로 반복 | 파생 제목과 본문 미리보기의 중복을 제거한다. 원문은 변경하지 않는다. |
| 선택하지 않은 상세 영역이 넓게 상주 | 선택 전에는 접고 기록 선택 후 연다. |
| 플로팅 입력창이 비어 있어도 큰 면적 차지 | 기본 3~4줄 입력, 내용 증가 시 제한된 확장. TODO 노출을 보존한다. |
| 입력과 안내문구가 겹쳐 보임 | 입력/붙여넣기/한글 조합/초안 복구 상태별로 placeholder를 검증한다. |
| 대부분의 조작이 비슷한 파란 둥근 버튼 | 주요 행동·보조 행동·탐색·선택 상태를 구별한다. |
| 파일 버튼만으로는 이미지 붙여넣기를 알아보기 어려움 | 짧은 안내와 첨부 미리보기, 드롭 피드백으로 기능을 드러낸다. |

## 3. 시각 기준 — 새로운 브랜드를 만들지 않는다

아래 수치는 이 프로젝트의 제안 작업값이다. 일반적인 표준이나 검증된 최적값을 뜻하지 않는다. WPF에서는 DIP를 사용하고 물리 픽셀과 구별한다.

기존 팔레트를 유지한다:
- 바탕 #F6F8FC, 표면 #FFFFFF, 보조 표면 #EFF3F8.
- 본문 #172033, 보조 글자 #526078.
- 강조 #3568E8, 강조 배경 #EAF0FF, 완료 #1D7A50.
- 경계 #DCE3ED. 모든 영역을 테두리 상자로 둘러싸지 않는다.
- 간격 4/8/12/16/24/32, 버튼·입력 반경 8, 카드 반경 12.
- 화면 제목 22 Semibold, 카드 제목 15 Semibold, 본문 14, 메타정보 12~13.
- 본문 줄 간격은 약 20 DIP를 출발점으로 하되 한글 받침 잘림을 실제로 검수한다.
- 본문은 설치된 Windows 한국어 기본 글꼴을 사용한다. 폰트 다운로드는 추가하지 않는다.
- 아이콘은 기존의 라이선스 확인된 로컬 벡터 한 세트. 이모지나 서로 다른 아이콘 세트 혼용 금지.

강조 규칙:
- 플로팅 창의 가장 강한 채움 버튼은 ‘기록’이다.
- 날짜 이동과 첨부는 보조 조작으로 표시한다.
- 탐색 항목과 보기 전환은 현재 선택을 보여주는 컨트롤이지, 모두가 주요 실행 버튼인 것은 아니다.
- 완료는 체크 아이콘+‘완료’ 텍스트로 구별한다. 색만으로 상태를 전달하지 않는다.
- 장식 그림자보다 여백·정렬·타이포 계층을 우선한다.
- 한글 폰트, placeholder, 파일명, 버튼 텍스트에 같은 글자 체계를 적용한다.
- **플로팅만 SUPERSEDED BY docs/FLOATING_CAPSULE_V2.md:** 기본 제목표시줄을 유지하라는 허용은 폐기한다. 메인은 기존 크롬을 유지한다.

최소 공통 컴포넌트:
- QuickCaptureComposer: 메인/표본용 세로 입력. **플로팅에는 넣지 않는다.**
- CapsuleInputBar / FloatingAuxiliaryPanel / CompactLogRow / CompactTodoRow: 플로팅 캡슐 전용.
- WorkItemRow: 체크·제목·선택적 이슈·완료 피드백.
- TimelineEntryCard: 메모·이미지·파일 기록.
- TimelineEventRow: 할 일 생성·완료·재열기·취소.
- DayViewSwitcher: 시간순/파노라마/업무별 선택.

프리뷰와 실제 제품은 같은 컴포넌트와 같은 템플릿을 사용한다. 프리뷰용 별도 예쁜 컨트롤을 만들지 않는다.

## 4. 플로팅 창: F01

**SUPERSEDED BY docs/FLOATING_CAPSULE_V2.md.** 이 절의 세로 메모장 구조는 폐기한다. QuickCaptureComposer를 플로팅에 넣지 않는다. 메인 타임라인 컴포넌트는 유지한다.

### 4.1 구조

기본은 한 줄 캡슐이다.

- 로고 메뉴(하루의 흐름 / 긴 메모 / 항상 위 / 숨기기 / 저장 위치 / 종료).
- 한 줄 입력과 인라인 기록·영역 캡처·첨부·할 일·최근 기록.
- 최근 기록/TODO/긴 메모·첨부는 아래(또는 위)의 작은 패널 하나. 상시 TODO·빈 추가칸·제목표시줄 없음.

### 4.2 크기

**SUPERSEDED BY docs/FLOATING_CAPSULE_V2.md.** 360 DIP 세로 폭, 80~96 DIP 기본 편집기, 빈 상태 280~340 DIP, 상시 TODO로 높이를 늘리는 규칙은 폐기한다.

- 기본 가시 캡슐 520×52 DIP, 끝 반경 26 DIP.
- 한 줄 입력은 높이를 키우지 않는다. 긴 메모·첨부·할 일·최근 기록은 작은 패널 하나.
- 패널이 없으면 실제 창 bounds도 축소한다. 구형 사용자 지정 세로 높이는 캡슐에 복원하지 않는다.
- 패널은 작업 영역 안에서 아래 또는 위로 연다. 캡슐 앵커는 유지한다.

### 4.3 입력·상태

빈 입력:
- placeholder: ‘지금 남겨둘 내용이 있나요?’
- 짧은 보조 안내: ‘이미지 붙여넣기 · 파일 끌어놓기’.
- 텍스트와 첨부가 모두 없으면 ‘기록’ 비활성화.

편집 중:
- placeholder를 본문 문자열로 넣지 않는다.
- 실제 편집기의 텍스트/IME 상태에 맞춰 즉시 숨긴다. 지연된 ViewModel 값만 보고 겹치게 두지 않는다.
- 안내 장식은 클릭과 텍스트 선택을 가로채지 않는다.
- **SUPERSEDED BY docs/FLOATING_CAPSULE_V2.md:** 한 줄 모드 Enter는 기록, Ctrl+Enter도 동일. 긴 메모 패널에서만 Enter 줄바꿈. 한글 조합 확정 Enter는 기록 금지.
- 단축키를 몰라도 ‘기록’ 버튼으로 사용할 수 있어야 한다.

첨부:
- 사용자가 붙여넣거나 놓은 이미지가 썸네일로 나타난다.
- 일반 파일은 파일명·형식·크기·제거 조작이 보인다.
- 첨부만으로도 기록할 수 있다.
- 드래그 진입 시 드롭 가능 영역을 알려주고, 실패하면 원문·기존 첨부를 보존한다.

저장:
- 초안 보관과 타임라인 기록을 구별한다.
- 성공 후 입력/첨부를 비우고 ‘09:42 타임라인에 기록했어요 · 기록 보기’처럼 짧게 확인한다.
- 직전 기록 성공 문구를 다음 초안의 저장 상태인 것처럼 계속 표시하지 않는다.
- 실패하면 입력을 유지하고 ‘기록하지 못했어요 · 다시 시도’를 제공한다.

할 일:
- ‘+ 할 일 추가’로 하단에 입력 행을 펼친다. 공백만 추가하지 못한다.
- Enter 또는 명시적 추가 버튼으로 추가하되 IME 조합 확정과 충돌하지 않는다.
- 체크 성공 후 활성에서 제거하고 타임라인 완료 이력을 남긴다.
- ‘완료 기록이 남았습니다 · 실행 취소’가 보인다. 기존 재열기 이벤트 정책을 유지한다.
- 이 목록에는 완료 항목을 다시 쌓아두지 않는다.

## 5. 하루 타임라인: T01

### 5.1 정보 구조

전역 탐색: ‘하루의 흐름’, ‘할 일’, ‘검색’, 하단 ‘설정’.
날짜 선택: 선택 날짜와 이전/다음, ‘오늘’ 복귀.
보기 전환: ‘시간순 | 파노라마 | 업무별’.

세 축을 같은 수준의 메뉴 버튼으로 섞지 않는다. 시간순을 선택했으면 시간순 내용이 나타나고 선택 상태와 화면이 일치해야 한다.

### 5.2 화면 구조

- 메인 첫 진입은 시간순 보기. 기록 선택 없음.
- 우측 상세는 선택이 있을 때만 연다. 미선택일 때 너비 352 DIP의 빈 열을 남기지 않는다.
- 좌측 탐색은 기존 176 DIP를 출발점으로 한다.
- 우측 상세는 352 DIP를 출발점으로 하되 중앙 가독성이 부족하면 오버레이로 바꾼다.
- 좁은 창은 축소 탐색을 사용한다. 화면을 통째로 줄이는 Viewbox 방식은 쓰지 않는다.
- 상세를 닫아도 날짜·필터·스크롤·선택 위치 문맥을 잃지 않는다.
- 장문의 ‘기록 시각은 작업 시작이 아닙니다’ 문구는 도움말에 두고, 실제 발생/기록 시각 구분은 필요한 카드/상세에서 정확하게 표시한다.

상단에는 제목/날짜, 작은 집계, 보기 전환을 배치한다. 통계 카드를 늘려 타임라인을 아래로 밀지 않는다.

### 5.3 사건 표현

- 왼쪽 시간 열 64 DIP, 노드/축 열 24 DIP, 나머지는 내용.
- 시간 라벨은 카드 첫 줄과 정렬한다.
- 기본 노드 약 8 DIP, 연결선 약 1 DIP. 사용 가능한 공간과 배율에서 선명도를 검수한다.
- 메모 카드는 제목·본문 미리보기·첨부·연결 정보를 내용에 따라 표시한다.
- 첫 줄을 제목으로 사용했다면 동일 문장을 본문 미리보기에 다시 반복하지 않는다. 저장된 원문은 바꾸지 않는다.
- 메모에 의미 없는 ‘메모’ 설명 행을 매번 덧붙이지 않는다. 유형 표시는 다른 유형과 구별하는 데 필요한 만큼만 한다.
- 완료/재열기는 별도 간결한 이벤트 행. 짧은 상태 이벤트를 큰 빈 카드로 만들지 않는다.
- 이미지 기록은 이미지 자체를 보여준다. 첨부는 최대 3개 미리보기와 +N 상세 접근.
- 긴 텍스트는 2~3줄 후 상세로 접근한다.
- 카드 사이 간격은 12~16 DIP를 출발점으로 한다.
- 시간순 보기에서 ‘업무 미연결 / 그룹’이라는 별도 큰 카드를 만들지 않는다.
- 업무별 보기에서는 ‘연결하지 않은 기록’처럼 이해 가능한 그룹 이름을 사용한다. 데이터 자체는 미연결 상태로 보존한다.
- 빈 시간을 가짜 근무시간 막대로 채우지 않는다.

### 5.4 데이터 수별 상태

0개: ‘아직 기록이 없어요’와 ‘첫 기록 남기기’. 설명용 빈 상세 패널은 없다.
1개: 실제 시각·노드·기록 한 개. 화면을 채우려고 내용을 중복하거나 가짜 기록을 넣지 않는다.
12개: 메모·이미지·파일·완료/재열기 혼합. 서로 다른 유형이 구별되고 근거를 열 수 있다.
50개 이상: 읽는 위치, 가상화, 새 기록 안내가 유지된다. 크기를 지나치게 줄여 우겨 넣지 않는다.

## 6. 파노라마의 범위

파노라마는 핵심 기능이다. 이번 1차 재작업이 두 화면에 집중된다는 이유로 기능 목록에서 삭제하지 않는다.

기존 파노라마가 있으면 진입 경로와 상태 일관성을 보존한다. 아직 없다면 화면에서 작동하는 척하지 않고 미구현 상태를 보고한다. 다음 UI 단계에서 24시간 미니맵과 시간대별 확대 목록을 별도 승인한다.

파노라마 검수 원칙:
- 기록 시각을 실제 작업시간 막대로 오해시키지 않는다.
- 미니맵은 하루 전체, 확대 영역은 현재 보는 범위임을 구분한다.
- 밀집 기록은 겹치거나 사라지지 않고 모두 접근 가능하다.
- 시간순과 파노라마에서 동일한 사건은 동일한 상세를 연다.

## 7. WPF 구현 기준

실제 프로젝트가 WPF일 때 적용한다. 다른 스택이면 개념만 대응시키고 이전하지 않는다.

- App 리소스 및 병합 순서, 지역 Style 우선순위를 조사한다.
- Style은 속성 통일, ControlTemplate은 컨트롤의 시각 구조, DataTemplate은 기록 유형의 표현을 담당하도록 나눈다.
- 기본 컨트롤의 입력·명령·키보드·접근성을 유지한다. 클릭 가능한 Border만으로 버튼을 대체하지 않는다.
- 기존 공통 템플릿을 개선하고 프리뷰/실화면이 공유하도록 한다.
- Normal/Hover/Pressed/Disabled/KeyboardFocus/Selected 상태를 해당 컴포넌트에 맞게 정의한다.
- Placeholder와 실제 TextBox 입력을 분리하고 입력·포커스·IME·초안 복구로 상태를 검증한다.
- 모든 상태가 애니메이션에 의존하지 않도록 한다.
- 본문 가독성·레이아웃 반올림·DPI는 실제 Windows 화면에서 확인한다. 픽셀 이미지 한 장으로 렌더링 문제를 단정하지 않는다.
- WPF Fluent 테마는 기반 후보이지 완성된 FlowNote 디자인이 아니다. 여러 UI 라이브러리를 섞지 않는다. 새 기반을 도입할 때는 작은 컴포넌트 표본에서 먼저 호환성을 확인한다.
- 코드 컴파일 성공은 시각 승인이나 사용성 검증을 뜻하지 않는다.

## 8. 진행 순서와 중단 지점

한 번에 아래 한 단계만 실행한다. 단계 종료 때 실제 결과를 제출하고 다음 단계로 자동 진행하지 않는다.

### U0 — 현황 확인과 컴포넌트 표본

기존 화면/코드를 확인해 ‘관찰 → 실제 원인 → 수정 파일 → 재현 방법’을 기록한다.
현재 코드가 사용하는 공통 컴포넌트를 재사용해 개발 전용 프리뷰를 만든다.
QuickCaptureComposer, WorkItemRow, TimelineEntryCard, TimelineEventRow의 기본/선택/오류 표본을 실제 실행한다.
DB 스키마를 변경하지 않는다. 운영 데이터와 분리된 합성 fixture를 사용한다.

종료 산출물: 코드 변경 목록, 실제 컴포넌트 캡처, 미검증 사항.
시각 승인권자: 발주자 또는 지정 디자이너. worker 자신의 ‘세련됨’ 평점으로 승인하지 않는다.

### U1 — 플로팅 창

승인된 컴포넌트로 F01만 정리하고 실제 기록/첨부/완료 서비스에 연결한다.
빈 상태, 한글 입력, 이미지 첨부, 할 일 3개, 기록 실패를 실제 실행·캡처한다.
‘메모 입력 → 첨부 → 기록 → 완료 → 실행 취소’를 짧은 실제 동작 영상으로 제출한다.
새 코드가 입력 포커스를 훔치거나 초안을 지우면 수정 후 재검수한다.

### U2 — 대표 타임라인

시간순 보기의 헤더/축/카드/상세를 재작업한다.
0개/1개/12개/밀집 기록으로 캡처한다. 제목 중복과 그룹 레이블 노출을 제거한다.
기록 선택/상세 닫기/날짜 이동/뷰 전환/실시간 추가의 상태를 검증한다.

### U3 — 파노라마 및 전체 회귀

앞 단계 승인 후 파노라마를 동일 디자인 시스템으로 개선한다.
기존 저장·시간·이력·파일·검색 테스트와 Windows UI 회귀를 실행한다.
화면 간 스타일만 맞추고 핵심 동작이 깨진 결과는 납품하지 않는다.

## 9. 승인 기준

### 기능 기준

기존 저장/초안/완료/재열기/첨부 검수 유지. 재실행 후 데이터가 동일해야 한다.

### 시각 기준

- 입력·안내문구 겹침 0건.
- 주요 조작 잘림/화면 밖 이탈 0건.
- 시간순 보기의 시간축·노드·기록 구조 확인.
- 미선택 상세가 차지하는 빈 열 없음.
- 파생 제목/본문 중복과 의미 없는 그룹 레이블 없음.
- 기본·포커스·선택·실패 상태의 구별.
- 실제 데이터 1개인 화면도 자연스러워야 함. 데모로만 통과하지 않음.
- 동일 논리 창 크기와 배율에서 승인된 기준 화면과 구현 화면을 비교.
- 100/125/150/200% 배율에서 가능한 작업 영역을 사용해 검사. 물리 해상도만 같다고 동일 조건으로 보지 않음.
- 모든 캡처에 빌드/클라이언트 DIP/물리 픽셀/배율/fixture/실행 환경 기록.
- 생성 이미지와 실제 실행 캡처를 나란히 놓고 단순 픽셀 유사도로 승인하지 않음. 승인된 실제 컴포넌트/화면을 이후 회귀 기준으로 삼음.

### 설명서 없는 사용성 검증

프로젝트를 처음 보는 사람에게 조작 방법을 설명하지 않고 목표만 제시한다.
- 메모 한 줄을 남겨 보세요.
- 이미지 한 장을 기록에 붙여 보세요.
- 할 일을 추가하고 완료해 보세요.
- 방금 완료한 일을 하루 기록에서 찾아 보세요.
- 실수로 완료한 일을 되돌려 보세요.

성공/실패, 망설인 위치, 잘못 누른 조작, 질문한 내용을 기록한다. 팀 내부자나 worker만의 테스트를 ‘초보자 사용성 검증 완료’로 표현하지 않는다. 이 작은 검증으로 전체 시장의 사용성을 입증했다고도 주장하지 않는다.
